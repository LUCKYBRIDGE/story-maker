# Work 연속 실행 최적화 요약

이 문서는 새 규칙을 만들기 위한 문서가 아니라, Codex Work가 긴 개발 세션에서 낭비 없이 실행할 수 있도록 기존 규칙을 짧게 요약한다. 충돌 시 `AGENTS.md`와 `docs/storygame-ai-implementation-runbook.md`가 우선한다.

## 기본 동작

- 한 번에 하나만 `IN_PROGRESS`로 둔다.
- 현재 작업이 `DONE`이고 다음 의존 작업이 명확하면 사용자 응답을 기다리지 않고 같은 milestone 안에서 계속한다.
- milestone 종료, BLOCKED, 제품 계약 변경, 데이터 손실·배포·비용·권한 같은 고위험 결정에서만 멈춘다.

## 토큰 절약

세션 시작 시 저장소 전체를 읽지 않는다.

1. `npm run status:check`
2. 현재 `READY`/`IN_PROGRESS`
3. 해당 작업 카드의 관련 절
4. 영향받는 소스와 가장 가까운 테스트
5. 충돌이 있을 때만 상세 설계·ADR·목업 추가 조회

이미 읽은 동일 문서, 완료 이력, 모든 작업 카드, 모든 ADR을 반복 순회하지 않는다.

## 최소 검증

- 문서만 변경: 링크·경로·충돌만 확인, build/test 생략
- 국소 로직: 가장 가까운 테스트만 우선
- UI: 관련 자동 검사 + 대표 흐름 1~2개
- 저장/스키마/호환성: 관련 fixture와 회귀만 확대
- 전체 `npm test`/smoke: 릴리스, 공용 핵심 변경, 빌드 체계 변경 등 넓은 영향에서만 수행
- 같은 commit에 대해 CI가 이미 통과한 명령은 Work에서 반복하지 않는다.

## 보고

작은 작업마다 장문 보고하지 않는다. milestone 체크포인트에서만 다음 정도로 요약한다.

```text
[완료] 핵심 결과
[검증] 실제 실행한 최소 검증
[다음] 바로 이어갈 작업
```
