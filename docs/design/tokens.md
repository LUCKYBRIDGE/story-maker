# 놀퀴즈 스토리 스튜디오 디자인 토큰

- 기준일: 2026-08-24
- 기준 소스: `app/globals.css`
- 목적: 학생의 글쓰기를 앞세우는 따뜻한 종이·민트 계열 UI를 일관되게 유지

## 1. 색상

| 토큰 | 값 | 용도 |
|---|---:|---|
| `--paper` | `#f7f3e9` | 전체 배경 |
| `--paper-deep` | `#eee5d5` | 구분된 보조 배경 |
| `--white` | `#fffdf8` | 카드·입력 배경 |
| `--ink` | `#183331` | 제목·주요 본문 |
| `--ink-soft` | `#4c625f` | 보조 설명 |
| `--line` | `#d8d0c2` | 테두리·구분선 |
| `--mint` | `#d6eadf` | 선택·안내의 옅은 배경 |
| `--mint-strong` | `#2f7d68` | 주요 버튼·초점·성공 상태 |
| `--gold` | `#e7aa42` | 이야기 단계·강조 |
| `--gold-soft` | `#f8e6b8` | 따뜻한 보조 강조 |
| `--coral` | `#d8644d` | 경고·삭제 |
| `--navy` | `#163943` | 플레이·강한 대비 배경 |

색만으로 현재 상태, 오류, 선택 여부를 표현하지 않는다. 텍스트, 아이콘, 테두리
또는 위치 정보를 함께 사용한다. 새 색상은 기존 토큰으로 표현할 수 없는 의미가
있고 대비를 확인한 경우에만 추가한다.

## 2. 타이포그래피

### 기본 글꼴

```css
Pretendard, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif
```

이야기 제목처럼 제한된 강조 영역만 다음 계열을 사용할 수 있다.

```css
"Iowan Old Style", "Noto Serif KR", serif
```

### 권장 크기

| 용도 | 크기 | 줄 높이 | 굵기 |
|---|---:|---:|---:|
| 화면 제목 | 28~36px | 1.2~1.3 | 700~800 |
| 영역 제목 | 20~24px | 1.3 | 700 |
| 카드 제목 | 16~18px | 1.35 | 700 |
| 본문·입력 | 15~16px | 1.5~1.7 | 400~600 |
| 보조 설명 | 12~14px | 1.4~1.6 | 500~700 |

초등 사용자용 필수 정보와 조작 문구에 12px 미만 글자를 사용하지 않는다. 현재
레거시 CSS의 8~11px 사용 구간은 접근성 개선 대상으로 관리한다.

## 3. 간격

4px 기준 격자를 사용한다.

- 미세 간격: 4px
- 같은 요소 안: 8px, 12px
- 입력·카드 안: 16px, 20px, 24px
- 영역 사이: 32px, 48px

새 임의 간격을 만들기보다 위 단계 중 가장 가까운 값을 사용한다.

## 4. 모서리와 그림자

| 용도 | 반지름 |
|---|---:|
| 작은 칩·입력 내부 | 8px |
| 입력·버튼 | 12px |
| 카드 | 16px |
| 큰 패널·모달 | 20~24px |
| 원형 선택 | 9999px |

- 큰 부유 패널: `0 20px 60px rgba(45, 53, 47, 0.12)`
- 작은 카드: `0 8px 24px rgba(45, 53, 47, 0.10)`

그림자는 계층을 설명할 때만 사용하며 카드마다 장식적으로 반복하지 않는다.

## 5. 상호작용

- 필수 터치 목표: 최소 44×44px
- 키보드 초점: `--mint-strong` 테두리와 명확한 외곽선
- 비활성 상태: 투명도만 낮추지 말고 가능한 경우 이유를 가까이 표시
- 위험 조작: `--coral`, 대상과 결과를 구체적으로 표시, 되돌리기 우선
- 움직임: 짧고 목적이 있어야 하며 `prefers-reduced-motion`을 존중

## 6. 반응형 기준

- 모바일: 320~767px
- 태블릿: 768~1024px
- 데스크톱: 1025px 이상
- 대표 검증: 390×844, 768×1024, 1024×768, 1440×900

모바일에서는 설명·설정을 접고 글 입력을 먼저 보인다. hover에만 나타나는 필수
기능을 두지 않으며, 키보드가 열린 상태의 화면도 별도로 확인한다.

## 7. 적용 원칙

1. 새 UI는 이 문서의 색·글자·간격을 우선 사용한다.
2. 기존 화면과 다를 때 임의로 둘 중 하나를 고르지 말고 기준 소스와 제품 의도를
   확인한다.
3. 토큰 변경은 시작·구상·대본·장면·플레이 전체에 미치는 영향을 검토한다.
4. CSS 전면 교체 대신 화면별로 이동하고 대표 크기에서 결과를 확인한다.
