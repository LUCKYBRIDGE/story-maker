# ADR — 캐릭터 포즈 세트 정렬·비율 표준 v1

- 상태: Accepted
- 결정일: 2026-09-03
- 범위: 기본 제공 캐릭터의 전신 이미지 생성, 보정, 교체와 등록
- 관련 문서:
  - `docs/storygame-detailed-design.md`
  - `docs/architecture/storymaker-system-asset-architecture-master-plan.md`
  - `docs/tasks/storygame-atomic-task-cards.md`

## 배경

같은 캐릭터의 감정·동작 이미지를 각각 생성하면 캔버스가 모두 `800 × 1200`이어도
머리 크기, 눈높이, 몸통 크기, 발 위치와 좌우 중심이 조금씩 달라질 수 있다. 이
차이는 플레이에서 표정이 바뀔 때 캐릭터가 커지거나 공중에 뜨는 것처럼 보이게
한다.

반대로 전체 알파 경계 상자만 같은 크기로 맞추면 늘어진 토끼 귀, 새우 더듬이,
용왕 뿔, 펼친 손과 소품까지 몸 크기로 오판한다. 자세의 의미를 보존하면서 같은
배우로 보이게 하는 별도 기준이 필요하다.

## 결정

### 1. 기준본과 위치 묶음

정렬 기준은 다음 키별로 하나의 승인 기준본을 둔다.

```text
작품 + characterId + designVersion + variantId + framing
```

- 감정과 짧은 동작은 새 Variant가 아니라 같은 기준본을 따르는 Pose다.
- 어린 시절이나 의상 교체처럼 의도적인 외형 변화만 별도 Variant로 둔다.
- 병듦·노화는 표정, 주름과 자세의 변화이며 머리를 임의로 크게 만드는 근거가
  아니다. 별도 Variant여도 같은 인물임을 알아볼 수 있는 머리/몸 비율을 유지한다.
- 캐릭터마다 기본 색감은 하나만 사용한다. 토끼의 신규 기본·감정 세트는 현재
  승인된 중간 회갈색 기준을 사용하며 더 밝은 색 변형을 섞지 않는다.

현재 `토끼와 자라` 전신 기준본은 다음과 같다. 새우 문관은 A1-02에서 정식
asset ID를 부여해 등록할 때 현재 승인 후보의 기본 자세를 기준본으로 확정한다.

| 인물 | 기준 asset ID | 비고 |
|---|---|---|
| 토끼 | `rabbit-turtle.character.rabbit-thinking` | 중간 회갈색·현재 얼굴과 체형 기준 |
| 자라 | `rabbit-turtle.character.turtle-resolve` | 현재 얼굴·등껍질·의상 비율 기준 |
| 용왕 | `rabbit-turtle.character.dragonking-recovered-unified-720x900` | 회복 상태의 소두형 비율 기준 |
| 의관 | `rabbit-turtle.character.physician-unified-720x900` | 현재 의관·청록 의상 기준 |
| 새우 문관 | A1-02에서 등록 | 현재 승인 후보의 기본 자세·자주색 관복 기준 |

### 2. 파일 표준

- 캔버스: `800 × 1200 px`
- 형식: 투명 배경 WebP 또는 PNG
- 바닥선: 알파 `10%` 이상인 발의 마지막 픽셀을 `y=1149`에 둔다. 따라서
  `y=1150..1199`의 하단 50px은 비어 있다.
- 머리 여백: 일반적인 선 자세의 머리 또는 모자 몸체 위에 120~180px을 둔다.
- 좌우 기준: 몸통의 시각 중심을 `x=400`에 두고 원칙적으로 ±12px 안에 맞춘다.
- 캐릭터가 캔버스 가장자리에서 잘리거나 알파 halo를 남기면 승인하지 않는다.

귀·더듬이·뿔·수염 끝, 펼친 손, 치마폭과 소품은 자세에 따라 움직이는 외곽이다.
이 끝점만을 맞추기 위해 전체 캐릭터 크기를 바꾸지 않는다.

### 3. 비교 기준과 허용 오차

전체 경계 상자 대신 다음 고정 기준점을 비교한다.

1. 발 바닥선
2. 몸통의 시각 중심
3. 두 눈의 평균 높이 또는 얼굴 중심
4. 어깨·가슴선
5. 귀·더듬이·뿔을 제외한 머리 폭과 높이
6. 머리 또는 모자 몸체 아래부터 발까지의 중심 신체 높이

| 항목 | 자동 통과 | 수동 검토 | 재생성 또는 교체 검토 |
|---|---:|---:|---:|
| 발 바닥선 | ±3px | 4~6px | 7px 이상 또는 발 잘림 |
| 몸통 시각 중심 | ±12px | 13~20px | 21px 이상이며 평행이동으로 해결 불가 |
| 눈높이·얼굴 중심 | ±12px | 13~24px | 25px 이상 |
| 중심 신체 높이 | 기준본 대비 ±3% | 3~5% | 5% 초과 |
| 머리/몸 비율 | 기준본 대비 ±3% | 3~5% | 5% 초과 |

수동 검토 구간은 바로 폐기하지 않는다. 자세, 원근과 소품 때문에 생긴 차이인지
동일 캐릭터 비율이 달라진 것인지 비교표에서 판정한다.

### 4. 보정과 재생성의 경계

다음 순서로 가장 비용이 작은 해결책을 먼저 사용한다.

1. **평행이동**: 비율이 맞고 발선·좌우 중심만 다른 경우
2. **균일 확대·축소 + 평행이동**: 머리/몸 비율은 같고 전신이 같은 비율로
   작거나 큰 경우. 발을 축으로 다시 고정한다.
3. **재생성**: 머리/몸 비율, 얼굴 정체성, 팔다리 길이, 의상 구조 또는 화풍이
   달라 균일 변환으로 해결할 수 없는 경우

금지 사항:

- 가로·세로 비율이 다른 비균일 확대
- 머리만 확대하거나 몸만 축소하는 부분 변형
- 귀·더듬이·뿔 끝을 맞추기 위한 전체 크기 변경
- CSS에서 자산별 임의 확대·이동으로 원본 결함을 숨기는 처리
- 승인된 asset ID·파일명·StoryProject 참조 변경

### 5. 제작·보정 절차

```text
기준본 잠금
  → 같은 기준본으로 Pose 생성
  → 800×1200 투명 캔버스 정리
  → 발선·몸통 중심·눈높이·중심 신체 높이 측정
  → 캐릭터별 전체 Pose 비교표 검수
  → NORMALIZE 또는 REFERENCE-REMAKE 판정
  → 무대 미리보기 검수
  → 최종 1회 인코딩
  → 기존 ID와 파일명 그대로 등록 또는 1:1 교체
```

- 원본과 보정 전 파일을 복구 가능한 작업 폴더에 보존한다.
- 위치 보정은 원본에서 다시 시작한다. 이미 압축한 결과를 반복 인코딩하지 않는다.
- 후보 단계에서는 손실 없는 중간 파일을 사용하고, 배포 파일은 한 번만 WebP로
  인코딩한다.
- 비교표에는 같은 캐릭터의 기준본과 모든 감정·동작 Pose를 함께 놓는다.
- 투명 체크무늬만으로 판단하지 않고 실제 무대 배경과 좌·우 배치에서도 확인한다.

### 6. Audit 결과

Audit은 각 파일에 다음 중 하나를 기록한다.

```text
KEEP
NORMALIZE-TRANSLATE
NORMALIZE-UNIFORM-SCALE
MANUAL-REVIEW
REFERENCE-REMAKE
REJECT
LEGACY
```

자동 검사는 캔버스, 알파, 바닥선, 가장자리 잘림과 측정 가능한 기준점 차이를
보고한다. 얼굴 정체성, 화풍과 의상 일치는 캐릭터별 비교표로 사람이 최종 승인한다.

현재 `scripts/prepare-story-assets.mjs`의 공통 trim/resize는 캔버스 규격을 맞추는
기존 호환 처리일 뿐, Pose 세트의 머리/몸 비율을 승인하는 검사가 아니다. A1-01의
읽기 전용 Audit이 측정과 판정을 담당하고, 생성기 변경은 A1-02에서 별도로 한다.

## 결과

- 같은 캐릭터가 감정에 따라 들썩이거나 갑자기 대두·소두가 되는 현상을 줄인다.
- 단순 위치 문제를 재생성하지 않아 이미지 생성 비용을 절약한다.
- 자세 변화와 실제 비율 오류를 구분하여 불필요한 확대·축소를 막는다.
- 기존 asset ID와 학생 작품 호환성을 유지한다.
- 기준점 metadata와 자동 Audit 도구를 추가하는 초기 비용이 생긴다.

## 인수 조건

1. 신규 전신 자산은 `800 × 1200`, 투명 배경과 `y=1149` 바닥선을 만족한다.
2. 같은 위치 묶음의 중심 신체 높이와 머리/몸 비율이 허용 오차 안에 있다.
3. 감정별 비교표와 실제 무대 미리보기에서 위치 튐이 보이지 않는다.
4. 균일 변환으로 해결할 수 없는 이미지만 재생성 대상으로 분류된다.
5. 교체 시 기존 asset ID, 파일명과 StoryProject 참조가 유지된다.
6. 원본과 보정 전 파일을 복구할 수 있고 최종 파일은 반복 손실 압축하지 않는다.
