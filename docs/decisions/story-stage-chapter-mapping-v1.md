# ADR — Story Stage Chapter Mapping v1 (다중 단계 연결형 이야기 흐름표)

- 상태: Accepted / Implemented
- 결정일: 2026-09-02
- 범위: 이야기 단계(발단·전개·위기·절정·결말)와 장(Chapter) 간의 다대다 매핑 데이터 계약 및 UI/UX 원칙

## 배경

기존 놀퀴즈 스토리 스튜디오는 1개의 장에 계산된 단일 이야기 단계 라벨을 순서 기반으로 균등 분배하여 표시했습니다. 그러나 실제 학생 글쓰기에서는 한 장 안에 여러 극적 사건(예: `위기`와 `절정`)이 동시에 발생하거나, 하나의 긴 단계(예: `전개`)가 여러 장에 걸쳐 이어지는 경우가 일반적입니다.

학생이 자신의 이야기 흐름을 스스로 구조화하고 성찰할 수 있도록, **한 장이 여러 단계를 동시에 담을 수 있고 같은 단계에 여러 장이 연결될 수 있는 다중 단계 연결 모델**을 도입합니다.

## 결정 사항

### 1. 이야기 위계 구조
- 전체 구조는 `이야기 단계(StoryStage) → 장(Chapter) → 컷(Line)`의 위계를 따릅니다.
- 장은 사건 흐름·기본 장소·등장인물의 묶음이며, 컷은 대사 또는 해설 한 줄과 개별 연출 단위입니다.

### 2. 데이터 계약 및 하위 호환 (`schemaVersion = 1`)
- `StoryStageKey`를 `"opening" | "middle" | "crisis" | "climax" | "ending"` 5개 정규 키로 정의합니다.
- `Chapter`에 `storyStageKeys: StoryStageKey[]` 필드를 추가합니다.
- `storyStageKeys`는 중복이 제거되고 정규 순서(`opening` → `middle` → `crisis` → `climax` → `ending`)로 정렬되어 저장됩니다.
- 빈 배열(`[]`)을 허용하며, 기존 v1 저장본이나 이전 Excel 파일에 해당 필드가 없는 경우 `[]`로 안전하게 정규화합니다.
- 스키마 버전은 `1`을 유지하여 기존 저장 키와 로컬스토리지 데이터를 파괴 없이 승계합니다.

### 3. 비채점형 고쳐쓰기 안내
- 단계가 연결되지 않은 장이나 장이 연결되지 않은 단계가 존재해도 스토리 플레이 및 적용을 차단하지 않습니다.
- 연결 상태는 채점이나 오류가 아닌 고쳐쓰기 자기 점검 가이드로 제공됩니다.

### 4. 플레이 순서와 단계의 분리
- 장의 순서(`order`)가 플레이 순서를 결정하며, 단계 선택은 장·컷의 ID나 플레이 순서에 영향을 미치지 않습니다.
- 계획용 단계 정보는 플레이어 화면에 기본 노출되지 않고 편집기 내부에서만 활용됩니다.

### 5. 구성 방식 전환 시 보존
- 3단계(처음-중간-끝), 4단계(발단-전개-위기-결말), 5단계(발단-전개-위기-절정-결말) 모드를 변경해도 기존 장에 연결된 `storyStageKeys`를 삭제하지 않고 보존합니다.

### 6. Excel 및 스프레드시트 호환
- `장의 흐름` 시트에 선택적 `이야기 단계` 열을 추가합니다.
- 한국어 명칭(`발단`, `전개`, `위기`, `절정`, `결말`, `처음`, `중간`, `끝`)과 영문 내부 키를 모두 인식합니다.
- 쉼표(`,`), 가운뎃점(`·`), 줄바꿈(`\n`)으로 구분된 다중 입력을 지원합니다.
- 알 수 없는 값은 탭·행·열·원문·수정 방법이 포함된 오류로 거부하여 현재 초안을 보호합니다.

### 7. 반응형 매트릭스 UI
- 데스크톱(1440×900): 행(장)과 열(단계)의 매트릭스 테이블로 한눈에 흐름을 조망.
- 태블릿(768×1024): 컴팩트 흐름표.
- 모바일(390×844): 단계 요약 바 + 장별 카드 + 단계 칩 (화면 축소 방지, 44px 터치 타깃 보장).
