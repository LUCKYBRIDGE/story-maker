## 맥락과 결정

기능이 이미 있는 MVP를 목업처럼 전면 재작성하지 않는다. 화면 수는 메인,
이야기 구성, 대본·컷 쓰기, 플레이 네 개로 제한하고 기존 데이터·저장·Excel
호환 위에 표현을 바꾼다. 독립 화면은 새 URL이나 라우터 도입을 뜻하지 않는다.

| 사용자 판단 | 상태 |
|---|---|
| 메인은 A안, “이야기를 만들어 볼까요?”, “새 이야기 만들기”, “이어만들기” | 확정 |
| Excel은 이어만들기의 한 방법, 미래에는 계정·클라우드도 고려 | 명칭 확정 / 계정·클라우드 구현은 별도 결정 |
| 이야기 구성은 편집과 별도 화면 | 확정 |
| 장 하나에 위기·절정 등 여러 단계, 단계 하나에 여러 장 | 확정·현재 데이터 지원 |
| 편집 F의 대본+무대, G의 컷 집중, D의 이미지 선택 원칙 | 선호 방향 확정 / 현행 치수 측정 완료 / 목표 배치는 후속 구현 검증 |
| 이야기 구성 01 장 목록+상세 | 2026-09-04 사용자의 최적안 선택 위임에 따라 채택 |
| 플레이는 원작 토끼와 자라·옹고집전의 연출 참고 | 방향 확정 / 두 이야기 지정 크기 비교 완료 / 목표 UI는 후속 검증 |

## 화면 경계

메인 → 이야기 구성 ↔ 대본·컷 쓰기 ↔ 플레이. 메인 복귀는 작품 삭제가 아니다.
새로 만들기·이어만들기 방식 선택, 이미지 선택, 파일·복구, 창작 메모는 해당
화면의 패널/대화상자다. 별도 장 구성 페이지나 템플릿 전용 사이트를 만들지 않는다.

계획은 선택적 도움이다. 장·단계·주제 작성 완료율로 대본 진입을 잠그지 않는다.
구성 01의 목록 하나와 선택 상세 하나를 폭에 맞춰 재배치한다.
다른 시안의 장점은 빈 상태·접기 등으로 차용하며 5개 모드를 만들지 않는다.

사용자가 “너가 생각할 때 최적의 안으로 진행해줘”라고 위임하여 01안을 선택했다.
넓은 화면은 목록+상세, 중간 폭은 접을 수 있는 목록+상세, 좁은 폭은 장 선택기와
상세 한 열이다. 04는 첫 장 추가 안내, 05는 선택 장 중심 배치만 차용한다.
이 결정은 디자인 방향 채택이며 새 UI의 반응형·접근성 검증 완료를 뜻하지 않는다.

## 상태와 데이터 경계

1. `draft`는 편집본, `active`는 명시적으로 적용한 플레이 스냅숏이다.
   화면 이동·이미지 미리보기·메인 복귀만으로 적용하지 않는다.
2. 작업 위치는 작품 ID + 장 ID + 컷 ID + 편집 보기 + 진입 화면으로 식별한다.
   순번은 표시/이동용이며 복귀 키로 쓰지 않는다.
3. “편집으로 돌아가기”는 플레이 진입 전 화면·보기·위치로,
   “이 컷 고치기”는 현재 재생 컷의 안정 ID로 이동한다.
   컷이 삭제됐거나 작품이 다르면 다른 컷을 같은 것으로 열지 않고 이유와
   안전한 편집 복귀를 제공한다.
4. 예시 플레이는 저장된 학생 작품과 독립된 재생 컨텍스트다. 닫으면 원래
   메인·active·편집 위치를 복원한다.
5. 재접속용 위치 저장이 필요하면 작품과 분리된 선택적 버전 키를 사용한다.
   손상·권한 거부는 작품 복원을 막지 않는다. 창 크기, caret, 패널 상태를
   Excel/StoryProject에 넣거나 schemaVersion을 올리지 않는다.
6. 리사이즈로 컴포넌트를 갈아 끼워 입력·선택·IME 조합을 잃지 않는다.
   일시적 caret/스크롤은 현재 세션 메모리에 두고, 재접속은 안정 ID 중심이다.

## 필드 계약

| 화면 문구/행동 | 기존 데이터 | 금지 |
|---|---|---|
| 이야기 제목·소개 | project.title / description | 안내문을 작품에 자동 입력 |
| 한 줄 이야기 | planning.premise | theme과 병합 |
| 주제·큰 생각 | planning.theme | 질문형 UI로 바꾸면서 기존 값을 덮어쓰기 |
| 이 장에서 일어나는 일 | Chapter.summary | keyEvents·purpose 삭제/합치기 |
| 자세한 장 계획 | purpose / mood / keyEvents / nextChapterIdea | 접힌 필드 누락 내보내기 |
| 이야기 단계·여러 개 선택 | Chapter.storyStageKeys | 단일 선택, 단계에 따라 장 자동 정렬 |
| 작품의 뼈대 | structureMode + opening/middle/crisis/climax/ending | 구조 변경 시 숨긴 메모 삭제 |
| 등장인물·배경 후보 | characterAssetIds / backgroundAssetIds / chapterSpeakerNames | 후보 추가를 전체 컷 교체로 취급 |
| 장의 기본 무대 | Chapter.backgroundId / leftAssetId / rightAssetId | 컷 override까지 덮어쓰기 |
| 이 컷에 사용 | StoryLine의 해당 이미지 필드 | 다른 컷·장 기본값 함께 수정 |
| 장의 기본으로 되돌리기 | 해당 컷 override 해제 | 장 기본을 현재 컷 이미지로 변경 |
| 화자·대사·해설 | speaker / speakerName / type / text | 이미지로 이름 강제, 해설에 화자 강제 |
| 창작 메모 | creativeMemos 및 편집 전용 note 필드 | 플레이 문장에 자동 합치기 |

`StoryPlanning`의 나머지 소재·인물·목표·갈등·세계·자유 메모도 접어서 보존한다.
공식 8개 탭과 이전 파일명/ID는 UI 명칭 변경과 분리해 유지한다.

## 적용 순서와 비용 통제

U1-01의 화면·필드 기준선과 U1-02 상태 계약은 완료했다. 이후 셸→메인→구성→장 조작→
공통 무대→편집→플레이 동작→플레이 표현→통합 검증 순으로 한 작업씩 적용한다.
카드·의존성·검사는 기존 실행 계획과 작업 카드에서 관리한다.

자산 taxonomy v2, IndexedDB 이전, 인증, 클라우드, 이미지 재생성, 새 디자인
라이브러리는 이번 UI의 선행 조건이 아니다. 기존 승인 캐릭터를 사용한다.
A1-02는 폐기하지 않고 우선순위상 유예한다. UI 완료가 자산 승인 완료를 뜻하지 않는다.
