## 0. 문서 운영과 현재 개발 상태

### 0.1 단일 기준 문서

제품 방향, 현재 구현 상태, 데이터 구조, 화면 원칙과 검증 기준은 이 문서를
기준으로 계속 갱신한다. 새 논의 문서를 기능마다 만들지 않는다.

- 사용자와 확정한 방향이 바뀌면 이 문서의 관련 본문과 현재 상태를 함께 고친다.
- 구현을 마치면 `현재 상태`를 갱신하고 실제 확인 방법과 남은 문제를 적는다.
- 코드와 문서가 다르면 차이를 숨기지 않고 `구현 필요`로 기록한다.
- `AGENTS.md`에는 작업 안전, 문서 우선순위, 상황별 책임 페르소나와 공통 완료
  기준을 유지하고 제품 세부 결정은 이 문서에 둔다.
- 날짜가 지난 임시 출력물보다 이 문서, 현재 앱 코드, 최신 공식 Excel 양식을
  우선한다.
- 완성 단계의 작업 순서와 페르소나·릴리스 문턱은
  `docs/storygame-completion-execution-plan.md`에서 관리한다.

상태 표현은 다음 네 가지로 통일한다.

| 상태 | 뜻 |
|---|---|
| 확정 | 이후 설계와 구현이 따라야 하는 제품 결정 |
| 구현됨 | 현재 코드에 반영되어 사용할 수 있음 |
| 검증됨 | 실제 파일·화면 또는 검사 명령으로 동작을 확인함 |
| 구현 필요 | 방향은 확정됐지만 현재 화면·파일에 아직 반영되지 않음 |

### 0.3 2026-07-28 확정 결정

1. 핵심 제작·저장·복구에는 자체 로그인과 Google 로그인을 요구하지 않는다.
2. 실시간 동기화가 아니라 사용자가 버튼을 누른 시점의 전체 작품을 저장하거나
   불러오는 스냅숏 방식을 사용한다.
3. Excel과 Google 시트는 서로 다른 작품 형식이 아니다. 같은 탭과 열을 가진
   `공통 작품 양식`을 기기 파일 또는 인터넷 시트로 다르게 보관할 뿐이다.
4. 웹은 주 편집 공간이고, 브라우저 자동 저장은 현재 작업 복구용이다.
5. Excel은 웹 편집본의 공식 내보내기·다시 불러오기·버전 보관 수단이다.
6. Google 시트는 공개 또는 웹 게시 주소에서 작품을 가져오는 읽기 전용
   수단이다. 웹에서 Google Drive로 직접 저장하지 않는다.
7. 웹에서 만든 작품을 Google 시트에서 사용하려면 Excel로 저장한 뒤 사용자가
   Google Drive에 올려 Google 시트로 연다.
8. Google OAuth, 시트 자동 생성, 웹과 시트의 자동 병합·실시간 연동은 현재
   제품 방향에서 제외한다.
9. 학생에게 보이는 주 작업 순서는 `이야기 구성 → 대본·컷 쓰기 → 플레이`로
   통일하고 웹과 파일에서 같은 용어를 사용한다.
10. `플레이에 적용`, `플레이`, 챕터 선택처럼 같은 기능을 한 화면에 반복하지
    않는다.
11. 인물·배경 세부 설정, 자유 메모, 장면 이동·복제·삭제는 없애지 않고
    `펼치기` 또는 `더보기` 안에 둔다.
12. 장의 흐름은 하나의 목록으로 표시한다. 선택 장의 상세는 같은 이야기 구성
    화면 안에서 넓은 폭에는 옆, 좁은 폭에는 아래 또는 선택 상세로 표시한다.

### 0.4 2026-09-04 목업과 구현 정합화

메인 A안의 두 진입과 문구, 별도 이야기 구성 화면, 대본/컷 두 보기,
원작을 참고한 플레이 방향을 반영한다. 구체적인 확정·제안 구분은
[화면 흐름 ADR](decisions/studio-screen-flow-v1.md)과
[목업 기준표](design/mockups/README.md)를 따른다. 이야기 구성 01안은 사용자의
최적안 선택 위임으로 채택했다. 본문은 목표 계약이며 변경 구현은 U1 카드에서
순서대로 수행한다. 계정·클라우드는 미래 고려 사항이지 현재 지원 기능이 아니다.

## 1. 제품 정의

학생이 놀퀴즈의 `토끼와 자라`, `옹고집전` 이미지를 고르고 대사와 해설을
써서, 웹·태블릿·모바일에서 바로 플레이하는 선형 스토리게임 제작 도구다.

한 학생이 기기 한 대에서 만드는 흐름을 기본으로 한다. 모둠은 한 기기를
함께 보며 역할을 나누거나, Excel 또는 Google 시트 한 부를 번갈아 편집한 뒤
대표 기기에서 불러올 수 있다. 자체 회원가입, 작품 저장 서버, 여러 기기의
실시간 공동 편집은 첫 버전에 두지 않는다.

아이디어 발상과 모둠 역할 나누기는 활동지로도 지원한다. 웹에는 활동지를
대신하거나 옮겨 적을 수 있는 `이야기 구성` 화면을 둔다. 구상 내용은
편집자에게만 보이는 창작 메모이며, 학생이 직접 만든 실제 대사·해설·이미지만
플레이 화면에 나타난다.

## 2. 최우선 원칙

1. 짧은 안내만 보고 5분 안에 첫 플레이 가능한 챕터를 만든다.
2. 학생은 코드, 좌표, 파일 경로를 직접 입력하지 않는다.
3. 편집 화면과 플레이 화면을 분리한다.
4. 편집 중인 내용은 플레이에 자동 반영하지 않는다.
5. 웹 입력은 기기에 자동 저장하고, 외부 파일과의 교환은 버튼을 눌렀을 때만 한다.
6. 이미지 파일과 화자 이름은 서로 독립된 값으로 다룬다.
7. 이미지 규격은 권장하되 조금 어긋나도 사용을 막지 않는다.
8. 캐릭터와 배경을 분리하고, 학생 화면에서는 `인물`, `감정`, `행동`, `구도`
   같은 한국어 분류 그룹을 사용한다.
9. 서버와 외부 API에 의존하지 않아도 핵심 편집과 플레이가 가능해야 한다.
10. 원본이 달라도 `불러오기 → 확인 → 플레이에 반영` 순서는 항상 같다.
11. 처음에는 글쓰기에 집중하고 이미지는 `보기 설정` 또는 선택 창을 열었을
    때만 크게 보여 준다.
12. 한 장에서 쓸 화자·캐릭터·장소를 먼저 좁혀, 컷 선택 목록이 과도하게
    길어지지 않게 한다.
13. 버튼은 영향을 주는 내용 가까이에 두고, 작품·장·컷 단위 조작을
    서로 섞지 않는다.
14. 편집 화면에 들어오면 설명보다 실제 대사·해설 입력칸이 먼저 눈에
    들어와야 한다.

## 3. 핵심 용어

| 용어 | 뜻 |
|---|---|
| 작품 | 학생이 만드는 스토리게임 한 편 |
| 화자 목록 | 작품에서 반복해서 선택할 글상자 이름 목록 |
| 장(場) | 사건의 흐름, 기본 장소와 등장인물 풀을 공유하는 이야기의 큰 묶음 |
| 컷(Cut) | 플레이 한 화면의 대사·해설과 개별 무대 연출 단위 |
| 장 기본 이미지 | 컷에서 별도 선택하지 않았을 때 쓰는 이미지 |
| 컷 이미지 | 그 컷에서만 기본값 대신 쓰는 표정·동작·배경 |
| 편집본 | 학생이 지금 수정 중이며 기기에 자동 저장되는 최신 내용 |
| 플레이 버전 | 마지막으로 `플레이에 반영`에 성공한 내용 |
| 공통 작품 양식 | Excel과 Google 시트가 함께 사용하는 동일한 탭·열 구조 |
| 불러오기 | Excel 또는 Google 시트 내용을 웹 편집본으로 가져오는 작업 |
| Excel로 저장 | 현재 웹 편집본을 새 `.xlsx` 파일로 내려받는 작업 |
| 외부 버전 | 특정 시점의 작품을 보관하기 위해 저장한 `.xlsx` 또는 같은 양식의 Google 시트 |
| 분류 그룹 | 인물·감정·행동·구도처럼 이미지 조건을 묶어 보여 주는 한국어 항목 |
| 검색 태그 | 정규 분류에 넣지 않는 세부 묘사를 이름 검색에서 찾기 위한 보조 단어 |
| 이야기 구성 | 소재·주제·이야기 핵심, 장의 흐름, 창작 메모 |
| 대본 전체 | 현재 장의 모든 컷 글을 순서대로 보는 편집 화면 |
| 컷 꾸미기 | 플레이와 비슷한 무대에서 한 컷의 글과 이미지를 고치는 화면 |
| 장의 자료 | 해당 장에서 고를 화자·캐릭터·배경을 미리 좁힌 목록 |
| 편집 전용 메모 | 창작을 돕지만 플레이에는 표시하지 않는 구상·감정·연출 기록 |

학생 화면에서는 `1장 · 1컷`을 사용한다. 컷은 대사뿐 아니라 해설과 이미지 중심
연출도 포함한다. 컷 번호는 순서에 따라 자동으로 붙고
학생이 직접 관리하지 않는다.

## 4. 확정된 데이터 흐름

### 4.1 기기 안 웹 편집

```text
웹에서 편집
  → 기기에 자동 저장
  → 플레이에 반영
  → 플레이 버전 교체
  → 필요할 때 Excel로 저장
```

웹 편집 내용은 입력할 때마다 기기에 자동 저장한다. Excel 또는 Google
시트로 자동 전송하지 않는다. 다른 버전으로 보관하려면 학생이 `Excel로
저장`을 누른다.

### 4.2 Excel 편집

```text
웹에서 Excel로 저장
  → Excel에서 여러 탭을 편집
  → 웹에서 Excel 작품 불러오기
  → 검사 결과 확인
  → 플레이에 반영
```

Excel 파일은 브라우저 안에서만 읽는다. 작품 파일을 놀퀴즈 서버로
업로드하지 않는다. 외부에서 바꾼 파일은 자동 감지하지 않으므로 다시
`Excel 작품 불러오기`를 해야 한다.

### 4.3 Google 시트 편집

```text
공통 작품 양식을 Google 시트에서 편집
  → 공개 또는 웹에 게시
  → 웹에 주소 입력
  → Google 시트 작품 불러오기
  → 검사 결과 확인
  → 플레이에 반영
```

Google 시트는 별도 작품 형식이 아니라 인터넷에 놓인 공통 스프레드시트다.
MVP는 공개 또는 웹에 게시한 Google 시트를 버튼을 누를 때 한 번 읽는
단방향 불러오기를 지원한다. 실시간 감시, 자동 새로고침, 웹에서 시트로
직접 저장은 하지 않는다.

비공개 시트는 사용자가 Google 시트에서 `.xlsx`로 내려받아 `Excel 작품
불러오기`로 가져온다. 이 방식은 놀퀴즈용 Google 로그인 화면, 자체 OAuth
프로젝트, 사용자별 API 토큰을 요구하지 않는다.

웹에서 고친 작품을 Google 시트로 옮기고 싶으면 `Excel로 저장`한 파일을
사용자가 Google Drive에 올려 Google 시트로 연다. Google Drive를 사용하는
과정에서 Google 계정이 필요할 수 있지만 놀퀴즈 스토리 스튜디오 안에서는
로그인하거나 권한을 연결하지 않는다.

### 4.4 충돌 원칙

- 웹 편집본과 Excel·시트 내용이 동시에 바뀌어도 자동 병합하지 않는다.
- 불러오기 전 현재 편집본은 자동 백업한다.
- 불러온 내용은 먼저 편집본이 되며 플레이 버전은 그대로 둔다.
- 학생이 내용을 확인한 뒤 `플레이에 반영`해야 실제 플레이가 바뀐다.
- 무엇이 최신인지 시간만으로 추측하지 않고, 학생의 마지막 버튼 선택을 따른다.

## 5. 창작 흐름

1. 메인에서 `새 이야기 만들기` 또는 `이어만들기`를 선택한다.
2. 새 이야기는 빈 작품/이어쓰기 템플릿을 고르고, 기존 이야기는 기기 저장본/
   Excel/공개 Google 시트 중 현재 가능한 방법으로 연다.
3. `이야기 구성`에서 작품 기본·큰 생각·장의 흐름을 정리한다. 필수 작성
   순서나 완료율 잠금 없이 바로 `이 장 대본 쓰기`로 갈 수 있다.
4. `대본·컷 쓰기`에서 대사·해설을 추가하고, 같은 컷을 `컷 꾸미기`로 연출한다.
5. `플레이에 적용`으로 편집본을 검증해 플레이 버전을 갱신한다.
6. `플레이`에서 읽고 `이 컷 고치기` 또는 `편집으로 돌아가기`로 고쳐 쓴다.

전체는 메인 / 이야기 구성 / 대본·컷 쓰기 / 플레이 네 화면이다. 단계는 자유롭게
왕복하며 화면 이동 자체는 데이터 초기화·플레이 적용을 하지 않는다.
저장이 실패해도 입력을 버리거나 성공으로 표시하지 않고 Excel 보관·재시도를 안내한다.

## 6. 시작 화면

[선택된 A안](design/mockups/home-a-v2.png)을 기준으로 두 개의 큰 진입을 둔다.

- 제목: **이야기를 만들어 볼까요?**
- 설명: 이야기를 쓰고, 무대를 꾸미고, 플레이하며 고쳐요.
- 왼쪽 주요 카드: **새 이야기 만들기**
- 오른쪽 보조 카드와 버튼: **이어만들기**
- 이어만들기 설명: **만들던 이야기를 계속 만들어요.**

`새 이야기 만들기`를 누르면 같은 화면의 선택 패널에서 빈 이야기 또는
기존 3개 이어쓰기 템플릿을 고른다. 템플릿은 새 작업의 출발점이며 저장본
이어만들기와 혼동시키지 않는다. 빈 작품은 현재처럼 장·컷 0개로 시작하고,
첫 장은 명시적 `장 추가`로 만든다.

`이어만들기`는 보관 방식에 독립적인 이름이다. 패널 안에 다음을 제공한다.

- 기기 저장본이 있으면 제목·저장 시각(확인 가능한 값만)과 `이 기기에서 이어만들기`
- `Excel 파일에서 불러오기`
- `공개 Google 시트에서 불러오기`

저장본이 없거나 읽기에 실패하면 상태·해결 행동을 보여 준다. 읽기 완료 전
기본 예시를 학생 저장본으로 표시하지 않는다. 저장본 바로가기를 오른쪽 카드에
넣을 수 있지만 A안의 두 진입을 별도 대시보드로 바꾸지 않는다.

새 작품·템플릿·가져오기가 현재 작업을 교체할 때 기존 확인/체크포인트 경로를
통일해 사용한다. 취소·오류·파일 선택 취소는 현재 작품을 유지한다. 같은 파일을
다시 고를 수 있어야 하며 이어만들기 수단을 바꿔도 작업을 잃지 않는다.

사용 방법과 예시 플레이는 보조 행동으로 둔다. 예시 플레이는 학생 작품을
덮어쓰지 않고 닫으면 메인으로 돌아온다. 그림은 `예시 화면`으로 식별하며,
목업용 그림을 실제 작품 썸네일로 위장하지 않는다.

“이야기는 이 브라우저에 저장돼요”와 Excel 별도 보관 안내는 유지한다.
Excel은 이 기기 안에서 읽고, 공개 시트는 한 번 가져오며 자동 동기화하지
않는다고 안내한다. 계정 연결·클라우드는 추후 별도 설계하며 지금 미구현
로그인/동기화 버튼을 노출하지 않는다.

### 6.1 이어쓰기 템플릿

처음부터 줄거리를 만드는 부담이 큰 학생을 위해 이야기의 앞부분이 준비된
이어쓰기 템플릿을 제공한다. 템플릿을 열면 원본을 직접 고치는 것이 아니라
이 기기에 새 편집본이 만들어진다.

첫 번째 템플릿은 `토끼와 자라 템플릿 1 · 땅에서 만난 뒤`다.

- 준비된 부분: `pinky-ne-site` 원작의 용왕의 병, 어린 자라를 구한 회상,
  토끼의 간 처방과 용왕의 명령, 자라가 땅에서 토끼를 마주하는 장면
- 학생이 시작하는 부분: 토끼가 자라의 첫마디를 기다리는 순간 다음,
  자라가 토끼를 용궁으로 데려가기 위해 하는 첫 말
- 기본 구성: `처음 → 중간 → 끝`
- 창작 메모: 자라의 목표와 문제, 학생이 결정할 질문만 제공
- 자유롭게 바꿀 수 있는 것: 제목, 주제, 인물 성격, 자라의 방법, 토끼의
  반응, 이후 장소와 결말

준비된 앞부분은 바로 플레이할 수 있다. 편집본에는 다음 챕터의 빈 대사
장면을 함께 두되, 학생이 글을 쓰고 `플레이에 적용`하기 전에는 빈 장면을
플레이 버전에 넣지 않는다. 템플릿 추가 시에도 `준비된 부분`과
`학생이 시작하는 지점`을 카드에서 분명히 표시한다.

템플릿을 연 뒤에는 `처음부터 읽고 고치기`와 `이어 쓸 곳으로`를 항상
제공한다. 준비된 앞부분도 잠긴 예문이 아니라 학생 작품의 일부이므로 대사,
해설, 이미지와 챕터 정보를 모두 수정할 수 있다. 장면 꾸미기의
`이전 장면`·`다음 장면`은 챕터 끝에서 멈추지 않고 다음 챕터로 이어진다.
따라서 학생은 첫 장면부터 이야기의 흐름을 연속으로 읽고 고친 뒤, 한 번의
버튼으로 원래 창작 시작 지점에 돌아와 뒷내용을 쓸 수 있다.

두 번째 템플릿은 `토끼와 자라 템플릿 2 · 용궁에 묶인 토끼`다.

- 준비된 부분: 첫 번째 템플릿과 같은 원작 앞부분에 이어, 원작 첫 선택 중
  `용궁 잔치로 초대한다`를 고른 고정 전개와 토끼가 용궁에서 결박되는 장면
- 학생이 시작하는 부분: 속았다는 사실을 알게 된 토끼가 살아남기 위해 하는
  첫 말
- 기본 구성: `발단 → 전개 → 위기 → 결말`
- 창작 메모: 토끼의 탈출 목표, 결박된 상황, 자라와 용왕이 내릴 수 있는
  선택을 질문으로 제공
- 자유롭게 바꿀 수 있는 것: 토끼의 꾀 또는 설득, 자라의 태도, 용왕의 반응,
  다른 치료법, 탈출 여부와 결말

템플릿 번호는 같은 작품 안의 시작 지점을 구별하기 위한 번호다. 학생이
템플릿 2를 사용하기 위해 템플릿 1을 먼저 완성할 필요는 없다.

세 번째 템플릿은 `옹고집전 템플릿 1 · 아내의 선택 이후`다.

- 준비된 부분: `pinky-ne-site` 최신 원작에서 가짜 옹고집이 엿을 나누고
  둘째의 까치 이야기를 끝까지 기다려 주어 아이들이 마음을 놓는 장면,
  진짜 옹고집이 돌아오자 아이들이 물러서고 가짜 옹고집이 앞을 막는 장면,
  첫 관아에서 두 옹고집이 같은 답을 하고 막내가 가짜 옹고집 뒤로 숨는
  장면과 아내가 `아이들을 지켜 준 저 사람과 돌아가겠습니다`라고 선택하는
  장면
- 학생이 시작하는 부분: 아내의 선택을 들은 직후 관아에서 나오는 첫 반응
- 기본 구성: `발단 → 전개 → 위기 → 결말`
- 창작 메모: 진짜 옹고집과 아내의 목표, 가족의 안전과 진실 사이의 문제,
  사또의 판결과 인물의 변화에 관한 질문을 제공
- 자유롭게 바꿀 수 있는 것: 선택 직후의 반응, 사또의 판결, 진짜·가짜
  옹고집과 가족의 행동, 이후 장소, 깨달음과 결말
- 기본 자료: 원작의 관아 마당, 눈길, 옹고집의 집 배경과 진짜 옹고집,
  가짜 옹고집, 부인, 사또, 포졸, 아이 이미지

세 템플릿은 서로 독립적이며 먼저 다른 템플릿을 완성할 필요가 없다.
준비된 장면은 원작의 해설·대사 순서와 배경 전환을 유지한다.
선택 버튼과 분기는 보여 주지 않고, 토끼와 자라 템플릿 2는 자연스러운
고정 경로 하나를 사용하며 옹고집전 템플릿은 아내가 가짜 옹고집을 선택한
경로를 고정한다.
원작에서 함께 배치된 전신 캐릭터와 배경 이미지를 기본으로
사용하며, 좌우 캐릭터는 서로 안쪽을 바라보도록 필요한 원본만 자동
반전한다. 이 배치는 플레이, 장면 꾸미기, 대본 전체 미리보기에 똑같이
적용한다.

## 7. 편집 화면

### 7.1 상단 공통 영역

작품 제목, 주 탐색(이야기 구성 / 대본·컷 쓰기 / 플레이), 실제 저장 상태,
파일·복구, 메인 복귀를 제공한다. 네이비 셸·흰 작업면·청록 행동은 목표
[디자인 토큰](design/tokens.md)을 따른다.

`플레이에 적용`과 `플레이`는 다른 행동이다. 적용은 도구 모음 한 곳에,
플레이는 주 탐색에 둔다. 목업처럼 같은 플레이 행동을 두 군데 반복하지 않는다.
좁은 화면에서는 위치를 옮길 수 있으나 상·하단에 동시에 고정하지 않는다.
작품 이름·긴 상태문이 주 입력 공간을 밀어내지 않도록 요약/펼치기를 사용한다.

### 7.2 작업 화면

`대본·컷 쓰기`는 같은 데이터를 보는 `이 장 대본`과 `컷 꾸미기` 두 보기다.
현재 구현의 “대본 전체”는 현재 장의 컷 목록이므로 작품 전체라는 오해가 없도록
범위를 명시한다. 전체 작품 대본 기능을 새로 추가하지 않는다.

#### 7.2.1 버튼 위치와 우선순위

| 범위 | 위치 | 행동 |
|---|---|---|
| 작품 | 공통 셸 | 메인, 파일·복구, 적용, 저장 상태 |
| 단계 | 주 탐색 | 이야기 구성 / 대본·컷 쓰기 / 플레이 |
| 장 | 한 번만 보이는 장 목록·선택기와 제목 | 이 장 대본, 장의 자료, 이 장부터 플레이 |
| 보기 | 편집 영역 위 | 이 장 대본 / 컷 꾸미기 |
| 컷 | 컷 행 또는 집중 편집기 | 종류·화자·본문, 이미지, 이전·다음, 추가 |
| 정리 | 해당 컷 더보기 | 위로·아래로·복제·삭제 |
| 참고 | 편집 영역에서 열기 | 창작 메모(플레이에 표시 안 됨) |

현재 위치는 `4장 · 4컷`을 먼저, `이 장 4/4 · 전체 13/16`은 필요할 때
보조로 표시한다. 숫자는 실제 정렬된 데이터에서 계산한다. 여러 단계는 줄바꿈
가능한 칩으로 표시하며 주제가 아니라 장의 역할임을 명시한다.

주요 행동은 구역당 하나를 원칙으로 한다. 대사·해설 추가는 나란한 의미 있는
버튼을 허용하되 삭제와 떨어뜨린다. 아이콘만 있는 필수 조작, hover 전용 버튼을
두지 않는다. 터치 영역 44px, 초점 표시와 한글 접근성 이름을 제공한다.

#### 7.2.2 실제 글쓰기 흐름

처음 편집에 들어오면 `이 장 대본`을 기본으로 한다. 이미 작업하던 보기·컷이
있으면 복원한다. F안처럼 무대와 대본을 함께 보되 작은 높이·키보드 사용 시
무대를 접거나 축소해 글쓰기를 우선한다.

컷은 독립 행이며 종류 → 대사일 때 화자 이름·위치 → 넓은 본문 → 꾸미기/더보기
순서로 읽힌다. 해설은 화자 조작을 숨긴다. 대사·해설 전환이 본문을 지우지 않는다.
괄호 속 감정·행동은 보조 표현으로 구분하지만 입력 원문을 임의로 재작성하지 않는다.

- 추가 후 새 입력칸에 초점, 이동·복제·삭제 후 인접한 유효 컷으로 초점 복원.
- Enter는 줄바꿈, 한글 조합 중 Enter는 컷 이동·추가로 가로채지 않음.
- 무대/대본 사이 왕복 시 안정 ID, 본문, 스크롤·가능한 선택 범위 보존.
- 입력은 자동 높이 확장하되 긴 본문이 전체 조작을 밀어내면 제한 높이+스크롤.
- 빈 이미지·빈 메모·단계 미연결은 대본 쓰기를 막지 않음.
- 컷 오류는 해당 행에 이유와 고치는 행동 제공.

G안의 `컷 꾸미기`에는 현재 위치·무대·현재 장의 컷 탐색·
`글 / 왼쪽 이미지 / 오른쪽 이미지 / 배경`을 둔다.
넓은 화면은 무대 옆 조작 패널, 좁은 화면은 아래 또는 시트형 패널을 쓴다.
목업의 긴 세로 페이지를 그대로 복제하지 않는다.

글 입력은 한 컷에 하나의 편집 지점만 둔다. 무대 글상자는 플레이 모양의 미리보기이고,
누르면 글 입력으로 초점을 옮길 수 있다. 무대와 별도 폼에 서로 다른 편집본을
두지 않는다. 이미지 탭은 이 장 후보·추천을 먼저, 전체 자료 찾기를 추가로 제공한다.
미리보기 선택 후 `이 컷에 사용`은 해당 필드만 변경하고 취소는 원래 값을 유지한다.
`장의 기본으로 되돌리기`는 컷 override만 해제한다. 장 기본 자체 변경은 별도 명시 행동이다.

컷 끝의 다음 탐색은 다음 장의 유효 컷으로 이어지고, 장 추가·컷 추가와 구분한다.
`이 장 대본으로`는 같은 컷을 선택해 돌아온다. 너비 변화로 편집 보기를
자동 전환하거나 입력 컴포넌트를 새로 마운트하지 않는다.

### 7.3 이야기 구성과 편집 전용 정보

이야기 구성은 대본 편집과 별도인 하나의 화면이다. 상단의 접을 수 있는
`작품 기본·큰 생각`, `장의 흐름` 목록 하나, `선택한 장 구성` 상세로 구성한다.
01안의 목록+상세를 채택한다. U1-01의 실측 기준선과 반응형 계약을 따르고 구현 후 치수를 검증한다.
현재의 이야기/장 탭과 흐름표·카드 중복은 목록+상세로 정리하되 데이터는 보존한다.

기본적으로 보이는 장 입력은 제목, `이 장에서 일어나는 일`, `이야기 단계·여러 개 선택`.
그 아래 `등장인물과 기본 무대`, `자세한 장 계획`을 접고
`이 장 대본 쓰기`를 선택한 장으로 연결한다. 장 0개는 짧은 안내와 `첫 장 추가`,
장 1개는 빈 슬롯/5단계 강제 없이 실제 장 한 개만 보여 준다.

데이터 대응은 [화면 흐름 ADR의 필드 계약](decisions/studio-screen-flow-v1.md#필드-계약)을 따른다.

- 큰 생각은 `planning.theme`, 한 줄 이야기는 별도 `planning.premise`.
- 이 장에서 일어나는 일은 `Chapter.summary`; purpose·mood·keyEvents·
  nextChapterIdea는 자세한 장 계획에 각각 남긴다.
- 소재, 인물·목표·갈등, 실패하면 생기는 일, 마지막 변화, 세계·자유 메모는
  기본·추가 설정으로 접어 보존한다. 표시를 줄인다고 저장·Excel 열을 없애지 않는다.
- 3·4·5단계 구조와 단계별 메모를 유지하고, 숨겨진 단계와 연결도 구조 전환 후 복구한다.
- 한 장에 여러 단계, 한 단계에 여러 장을 연결한다. 단계 선택에 따라 장을 자동 정렬하지 않는다.
- 순서 변경은 위로·아래로 버튼으로도 가능해야 하며 장/컷 ID·단계·메모 연결을 보존한다.
- 인물·배경 후보 목록과 장의 기본 배치는 다른 값이다. 후보 추가가 기본 변경을
  뜻하지 않으며 기본 변경은 상속하는 컷에만 반영된다.

단계와 기본 무대는 나중에 정해도 된다. 구성 점검은 접힌 참고 안내로 두고,
완료율·점수·필수 표시로 대본 진입을 막지 않는다. 짧은 이야기나 다중 단계 장을
오류로 취급하지 않는다. 별도 장 상세 페이지·단계별 작성 마법사는 만들지 않는다.

전체·장·컷 메모는 기존 창작 메모에서 같은 값을 수정한다. 플레이 본문과는 분리한다.

#### 7.3.1 자유 메모와 도움 틀

기본 `이야기 구성`은 작품 전체의 중심을 잡는 뼈대로 유지한다. 더 자세히
생각하고 싶은 내용은 `+ 창작 메모`에서 별도의 카드로 추가한다. 새 메모를
만들 때 먼저 다음 두 방식 중 하나를 고른다.

- `자유롭게 쓰기`: 메모 제목과 넓은 글쓰기 공간을 제공하며 여러 개 생성 가능
- `도움 틀로 쓰기`: 인물 알아보기, 인물 관계, 장소·세계, 사건·갈등 중 선택

도움 틀은 처음에 세 항목만 보여 준다. 나머지는 `+ 항목 추가`에서 추천
항목을 하나씩 고르거나 `직접 항목 이름 붙이기`로 만든다. 항목은 위·아래
버튼으로 순서를 바꾸고 삭제할 수 있다. 모든 항목은 선택 사항이며 빈 항목이
저장, 자동 저장, Excel 저장이나 편집을 막지 않는다. `어린 시절`처럼 특정
답을 강요하는 항목 대신 `과거의 중요한 일`처럼 여러 이야기에 쓸 수 있는
질문을 추천한다.

목록 카드는 메모 종류, 제목 또는 첫 대상, 내용 일부, 작성한 항목 수만
보여 준다. 모든 입력란을 목록에 펼치지 않고 `열기`에서 상세 편집한다.
메모 삭제에는 확인 절차를 두며, 상세 편집은 모바일에서 전체 화면으로 연다.

작품 데이터에는 `creativeMemos` 배열을 둔다. 메모는 종류, 제목, 선택적인
챕터·장면 연결, 표시 순서와 항목 배열을 가진다. 항목은 이름, 내용, 순서와
`기본`·`추천`·`직접 추가` 출처를 가진다. 이전 브라우저 저장본에 배열이
없으면 빈 배열로 보완하며 기존 이야기 구성·챕터·장면 메모는 변환하거나
삭제하지 않는다.

#### 7.3.2 편집 중 창작 메모 팝업

편집 화면의 창작 메모는 별도의 복사본이 아니라 `이야기 구성`, 챕터와
장면이 사용하는 같은 값을 직접 보여 준다. 한 곳에서 고치면 다른 모든
편집 화면의 표시도 바로 바뀌며, 별도의 메모 업데이트 버튼을 요구하지
않는다.

팝업은 기존 이야기 구성, 추가한 창작 메모, 챕터와 장면 메모를 함께 보여
준다. 기존 이야기 구성은 다음 세 묶음으로 유지한다.

1. `전체 이야기`
   - 한 줄 이야기·소재·주제
   - 핵심 인물, 바라는 것, 주요 갈등
   - 실패하면 생기는 일과 마지막 변화
2. `이야기 뼈대`
   - 선택한 3·4·5단계 구성
   - 발단·전개·위기·절정·결말 중 현재 구성에 쓰는 단계
3. `인물·배경·추가 메모`
   - 인물 설정, 배경·세계 설정, 전체 분위기
   - 아직 정하지 못한 것, 자유 창작 메모
추가한 창작 메모는 `자유 메모`, `인물`, `관계`, `장소·세계`,
`사건·갈등` 종류로 표시하며, 다음 두 묶음도 이어서 제공한다.

4. `현재 챕터`
   - 챕터 제목과 한 줄 줄거리
   - 챕터 역할·분위기
   - 꼭 들어갈 사건
   - 다음 챕터 아이디어
5. `현재 장면`
   - 장면 역할
   - 감정 메모
   - 연출 메모

`전체 이야기`, `현재 챕터`, `현재 장면`은 처음 열 때 펼쳐 두고 나머지는
접어 둔다. 각 묶음은 서로 독립적이므로 여러 묶음을 동시에 펼칠 수도 있고
하나만 남길 수도 있다. `모두 접기`로 글쓰기 공간을 빠르게 되찾는다.
팝업을 닫았다 다시 열어도 사용자가 펼쳐 둔 묶음과 선택한 검색 범위는
유지한다.

팝업 상단에는 항상 `메모 찾기`와 범위 선택을 둔다.

- 검색 대상은 메모 제목·종류·대상, 항목 이름·내용, 챕터명과 장면 번호다.
- 범위는 `전체`, `이야기 구성`, `인물`, `관계`, `장소·세계`,
  `사건·갈등`, `자유 메모`, `챕터`, `장면`으로 제공한다.
- 검색은 현재 챕터와 장면만이 아니라 작품의 모든 챕터·장면 메모를
  대상으로 한다.
- 결과에는 메모가 속한 챕터·장면, 메모 이름과 내용 일부를 함께 표시한다.
- 결과를 누르면 해당 챕터 또는 장면을 선택하고 메모 입력칸에 바로
  커서를 둔다.
- 검색 결과가 없으면 검색어를 줄이거나 범위를 바꾸라는 안내를 표시한다.

대본 전체에서 다른 장면의 글상자를 누르면 `현재 장면` 묶음도 해당
장면으로 바뀐다. 장면 꾸미기의 이전·다음 이동에서도 같은 규칙을
사용한다. 패널을 열거나 접는 행동은 선택한 챕터·장면, 입력 중인 글과
스크롤 위치를 바꾸지 않는다.

데스크톱에서는 글쓰기 영역 위에 비차단 메모 팝업을 띄운다. 팝업 뒤의
대본과 장면은 그대로 유지하며, 메모를 닫지 않아도 편집 위치를 잃지 않는다.

```text
┌──────────────────────────────────────────────┐
│ 대본 전체 또는 장면 꾸미기                     │
│                         ┌──────────────────┐ │
│ 대사·해설 쓰기           │ 창작 메모        │ │
│                         │ 메모 찾기·범위   │ │
│                         │ 검색 결과/메모   │ │
│                         └──────────────────┘ │
└──────────────────────────────────────────────┘
```

- 기본은 작게 보기로 열고 `크게 보기`, `작게 보기`, 글자가 있는 `닫기`를
  제공한다.
- 팝업을 닫아도 편집 도구의 `창작 메모` 버튼은 항상 남긴다.
- 묶음의 접힘 상태는 팝업을 닫고 다시 여는 동안 유지한다.
- 바깥 편집 화면을 어둡게 덮거나 조작을 막는 모달로 만들지 않는다.
- 팝업에는 이미지 미리보기를 넣지 않아 글쓰기 공간과 성능을 지킨다.

태블릿에서는 오른쪽에 겹쳐지는 팝업으로 열어 현재 편집 위치를 유지한다.
모바일에서는 `창작 메모`를 누르면 전체 화면 팝업을 연다. 어느 화면에서도
각 메모 묶음을 접고 펼칠 수 있다.

모바일 전체 화면 패널은 다음을 지킨다.

- 상단에 글자가 있는 `닫기`와 현재 `챕터 N · 장면 N`을 고정한다.
- 메모 묶음을 독립적으로 접고 펼친다.
- 닫으면 원래 편집 화면의 같은 장면과 대사 입력 위치로 돌아간다.
- 메모 수정은 기기에 자동 저장하며 플레이 화면에는 나타나지 않는다.
- 화면을 닫기 위한 작은 `×`만 두지 않고 글자가 있는 닫기 버튼을 제공한다.

메모가 길어도 편집 화면 전체를 밀어내지 않는다. 데스크톱 팝업과
모바일 전체 화면 패널은 내부에서 독립적으로 스크롤한다. 업데이트 진행
중에는 다른 편집 조작과 마찬가지로 메모 열기·수정도 잠근다.

### 7.4 챕터 자료 제한

각 챕터는 화자 이름, 캐릭터 이미지, 장소·배경 목록을 가진다. 장면의
드롭다운은 이 목록만 보여 준다. 필요한 자료가 없으면 `이미지 고르기`를 눌러
전체 이미지 선택 창에서 분류 조건·검색·즐겨찾기·최근 사용으로 찾는다.
자료를 고르는 것과 화자 이름을 정하는 것은 서로 독립이다.

### 7.5 자료 가져오기·내보내기

- `Excel 작품 불러오기`
- `현재 작품을 Excel로 저장`
- Google 시트 주소
- `Google 시트 작품 불러오기`
- `공통 작품 양식 받기`

자료 조작은 편집 탭과 분리된 한 영역에 모은다. Google 시트는 “공개 또는
웹에 게시한 시트만 가능”과 “불러온 뒤 원본과 자동 연결되지 않음”을 짧게
표시한다.

### 7.6 플레이 적용 영역

`플레이에 적용`은 현재 편집과 마지막 적용본이 다름을 알려 주는 한 곳의 행동이다.
적용할 내용 없음·처리 중·실패·중지 상태를 구분한다. 기본은 공통 도구 모음이며,
작은 화면에서 아래로 옮길 경우 입력·안전 영역·키보드를 가리지 않아야 한다.
화면 이동만으로 자동 적용하지 않는다.

## 8. 플레이 화면

플레이는 편집 도구를 숨기고 작품·장 제목, 현재 컷, 배경·인물·대사 또는 해설,
이전/다음, 처음부터/장 선택, 복귀 행동만 제공한다. 원작 참고의 위치·상태는
[목업 기준표](design/mockups/README.md#원작-플레이-참고)를 따른다.
원작의 분기·선택지·점수·저장 모델은 가져오지 않는다.

### 8.1 읽기와 무대

- 화자 이름은 대사와 구별되는 이름표 또는 명확한 이름 영역에 표시하고,
  해설은 화자 없이 별도 표현한다. 공백 이름은 다듬어 `화자 없음` 등 안전한
  안내로 처리하고 이미지에서 이름을 추정하지 않는다.
- 배경은 cover를 허용하되 전신 캐릭터는 비율을 유지하고 발·머리를 임의로 자르지 않는다.
  대사 영역을 포함한 가용 무대 높이에 맞춰 두 인물을 균일 배치한다.
- 같은 자산 해석·방향·기준선 규칙을 편집 미리보기·썸네일과 공유한다.
  캐릭터 기준 이미지·asset ID를 바꾸는 보정은 UI 작업에서 하지 않는다.
- 긴 대사·해설은 줄바꿈/스크롤하고 이전·다음 조작은 계속 접근 가능하게 둔다.
  글자를 과도하게 줄이거나 말풍선 높이를 고정해 본문을 숨기지 않는다.
- 없는 배경·캐릭터·이미지 로드 실패는 빈 상태/대체 표시로 처리하고 플레이를 깨뜨리지 않는다.
- 저작 메모·구상·감정 메모를 플레이 문장에 자동 덧붙이지 않는다.

### 8.2 위치와 복귀

`편집으로 돌아가기`는 플레이 진입 전 화면·보기·위치로 복귀한다.
`이 컷 고치기`는 현재 재생 중인 컷의 안정 ID를 draft에서 찾아 집중 편집한다.
active와 draft의 작품이 다르거나 해당 컷이 삭제됐으면 잘못된 순번을 열지 않고
이유·안전한 편집 복귀를 제시한다. 예시 플레이는 저장된 active를 교체하지 않고
닫으면 예시를 열었던 메인으로 돌아온다.

플레이 인덱스는 정렬된 유효 컷 길이에 맞게 하나의 값으로 정규화해 본문·표시
번호·이전/다음 활성 상태 모두에 사용한다. 장 0개·전체 컷 0개는 별도 안내,
빈 장은 시작 선택에서 제외한다. 상단의 “플레이”는 기본적으로 처음부터,
“이 장부터”는 그 장의 첫 컷이라는 기존 의미를 유지한다.

키보드 이전/다음은 입력·버튼·선택기·contenteditable의 본래 Enter/Space
동작을 가로채지 않는다. 초점 표시, 키보드만으로 닫기/복귀, 화면 읽기 순서를 확인한다.

## 9. 화자 이름 설계

### 9.1 이미지와 이름 분리

캐릭터 이미지는 외형, 표정, 동작만 정한다. 글상자 화자 이름은 학생이
만든 이야기 속 이름이다.

| 선택한 이미지 | 글상자 화자 이름 | 결과 |
|---|---|---|
| `토끼_놀람.png` | `토끼` | 토끼 이미지와 토끼 이름 |
| `토끼_놀람.png` | `달토끼` | 같은 이미지에 달토끼 이름 |
| `토끼_놀람.png` | `민수` | 같은 이미지에 민수 이름 |

이미지를 바꿔도 화자 이름은 바뀌지 않는다. 이름을 바꿔도 이미지는 바뀌지
않는다.

### 9.2 재사용 화자 목록

1. 기존 이름을 드롭다운에서 고른다.
2. 없으면 `+ 화자 추가`로 만든다.
3. 새 이름은 현재 장면에 바로 선택된다.
4. 이후 다른 모든 대사 장면에서도 계속 고를 수 있다.

해설 컷은 화자 이름을 요구하지 않고 `해설`로 구분한다. 캐릭터 이미지를
골랐다는 이유로 화자 이름을 강제하지 않는다. 해설의 표면·여백은 대사와
구별하되 긴 글은 왼쪽 정렬해 읽기 편하게 한다. 종이색·가운데 정렬을 강제하지 않는다.

U1에서는 플레이·무대 미리보기의 화자 이름을 별도 이름 영역으로 구분할 수 있다.
현재 소스의 `화자명:` 한 문단 표시는 기존 구현이며 새 디자인의 필수 제약이 아니다.
대본 행은 이름 조작과 본문을 분리하고, 작은 미리보기는 가독 공간에 맞게 요약한다.
화자의 좌우 위치가 글의 읽기 순서를 바꾸지 않으며 다음 입력의 의미를 보존한다.

- `어린 자라: (떨리는 숨을 고르며) 저는 민물에서 왔습니다.`
- `용왕: 그럼 이곳에서는 서두르지 않아도 된다.`

대사 장면에서는 학생이 속마음·표정·말투·짧은 행동을 직접 괄호 안에
쓴다. 별도 입력칸이나 자동 괄호는 두지 않는다. 플레이에서는 학생이 입력한
괄호를 유지하고, 괄호 부분을 화자명과 본문 사이의 같은 문장 흐름 안에서
대비를 충족하는 보조색·굵기로 표시한다. 한글 기울임은 필수로 하지 않는다.
괄호가 문장 중간이나 끝에 있어도 새 줄로
강제로 분리하지 않는다.

- `정말 용궁이 그렇게 멋져?`
- `정말이야? (자라를 의심스럽게 바라본다.)`
- `(아무래도 자라의 말을 그대로 믿으면 안 될 것 같아.)`

해설은 시간·장소·상황과 여러 인물에게 일어난 사건을 작가의 목소리로
연결하므로 괄호를 사용하지 않는다. 해설에 괄호가 있으면 해당 장면에
수정 안내를 표시하고 `플레이에 적용`을 멈춘다. 입력 내용을 자동으로
지우지는 않는다.

## 10. 이미지 도감과 선택

### 10.1 자료 구분

첫 단계에서 다음 두 종류를 명확히 나눈다.

- `캐릭터 이미지`
- `배경 이미지`

캐릭터 선택 칸에는 배경을, 배경 선택 칸에는 캐릭터를 넣을 수 없게 한다.

### 10.2 이미지 이름

학생이 이름만 보고도 대강 알 수 있게 `토끼_놀람.png`,
`자라_지침.png`, `용궁_환영연회장.png`처럼 표시한다. 원본 파일명이
어렵더라도 학생용 표시 이름은 한국어로 제공한다.

### 10.3 분류 조건과 검색 태그

학생 화면에는 `인물`, `감정·상태`, `행동`, `구도`처럼 뜻을 바로 알 수 있는
분류 그룹을 보여 주고, 각 값은 한국어로 제공한다. 개발자 용어인 `Facet`,
`AND`, `OR`은 학생에게 노출하지 않는다.

예:

- 작품: `토끼와 자라`, `옹고집전`
- 인물: `토끼`, `자라`, `용왕`, `옹고집`
- 감정·상태: `기쁨`, `슬픔`, `분노`, `놀람`, `걱정`
- 행동: `말하기`, `도망`, `부탁`, `건네기`
- 장소·장면: `마을`, `용궁`, `연회장`, `낮`, `밤`

같은 분류 그룹에서 여러 값을 고르면 그중 하나에 맞는 이미지를 보여 준다.
서로 다른 분류 그룹은 모두 만족하는 이미지로 좁힌다.

예를 들어 `인물: 토끼·자라`, `감정: 놀람·걱정`, `구도: 전신`을 고르면
`(토끼 또는 자라)이며 (놀람 또는 걱정)이고 전신인 이미지`를 보여 준다.
검색어는 이 결과에 추가로 함께 적용한다. 선택한 조건은 칩으로 보이고 하나씩
해제하거나 `선택 조건 지우기`로 초기화할 수 있다.

현재 v1 Picker의 자유 태그 전체 AND 방식은 호환 구현이다. 목표 검색 의미와
이전 순서는 `docs/decisions/story-asset-taxonomy-v2.md`를 따른다.

### 10.4 찾기 편의

- 이름 검색
- 여러 분류 값 선택
- `추천 이미지`와 `모든 이미지` 보기 범위
- `원작 사용`과 `추가 연출` 구분
- 캐릭터의 `전신`, `상반신`, `여러 인물` 구도 구분
- `즐겨찾기`
- `최근 사용`
- 썸네일 미리보기
- 결과 개수 표시

즐겨찾기와 최근 사용 기록은 작품 데이터가 아니라 해당 기기의 브라우저에
저장한다. 최근 사용은 가장 최근에 고른 순으로 제한된 개수만 유지한다.

### 10.5 이미지 선택

모든 이미지 입력은 두 방법을 함께 제공한다.

- 이름이 보이는 드롭다운
- `이미지 고르기`를 누른 썸네일 선택

장면별 선택에서는 `챕터 기본 이미지 사용`을 첫 항목으로 둔다. 이미지
썸네일은 창을 열었을 때 불러와 태블릿의 데이터와 메모리 사용을 줄인다.
기본 편집 화면은 `글만 보기`이며, `작은 그림 함께 보기`를 선택했을 때만
목록에 썸네일을 표시한다.

이미지 선택 창은 그림을 고르는 일이 필터 설정보다 먼저 보이게 구성한다.

1. 창 제목에서 캐릭터인지 배경인지와 바꿀 위치를 알려 준다.
2. 현재 장면에서 실제 보이는 이미지를 `현재 장면에서 사용 중`으로 먼저 보여
   준다. 장면값이 비어 챕터 기본 이미지를 쓰는 경우에도 실제 이미지를 표시한다.
3. 검색과 추천 이미지 목록을 먼저 보여 준다.
4. `조건으로 좁히기`를 눌렀을 때만 작품·인물·감정·행동·구도를 펼친다.
5. 선택 중인 조건 수와 결과 개수를 표시한다.
6. 카드에는 파일 이름, 쉬운 설명, 작품·구도처럼 선택에 필요한 정보만 남긴다.
7. 현재 사용 중인 이미지 카드에는 `현재 선택` 표시를 붙인다.
8. 그림을 누르면 즉시 선택하고 창을 닫는다.

선택 창은 장면 무대와 캐릭터 칸 안에 렌더링하지 않고 화면 최상단에 독립적으로
띄운다. 열려 있는 동안에는 뒤의 배경과 맞은편 캐릭터가 드러나지 않도록
불투명한 가림막을 사용하고 배경 화면 스크롤을 잠근다. 왼쪽 캐릭터를 고를
때는 왼쪽 후보 이미지만, 오른쪽 캐릭터를 고를 때는 오른쪽 후보 이미지만
보며 맞은편 캐릭터를 선택 창 안에 합성하지 않는다.

배경 후보는 캐릭터 카드와 같은 4:3 칸에 억지로 넣지 않고 16:9 미리보기로
보여 준다. 실제 무대처럼 `cover` 방식으로 보여 주어 선택한 뒤 화면 가장자리가
일부 잘릴 수 있음을 미리 확인할 수 있게 한다.

준비된 이미지 도감에서 고르는 버튼은 `이미지 고르기`, `다른 이미지
고르기`, `사용할 캐릭터 고르기`, `사용할 배경 고르기`로 쓴다. `자료
추가`처럼 새 파일을 업로드한다고 오해할 수 있는 표현은 쓰지 않는다.

이미지 선택 창은 `기본 추천`을 처음 상태로 사용한다. 기본 추천은 현재의
`배경 + 좌우 캐릭터 + 하단 글상자` 무대에서 서로 겹치지 않고 안정적으로
쓸 수 있는 자료다.

- 토끼와 자라: 크기와 기준선이 통일된 전신 캐릭터 7종, 캐릭터가 미리
  합성되지 않은 장소 배경 12종
- 옹고집전: 중복 구도와 어두운 실루엣을 걷어낸 전신 캐릭터 23종,
  캐릭터가 미리 합성되지 않은 장소 배경 7종
- 합계: 기본 추천 49종

상반신 변형, 비슷한 포즈의 중복본, 여러 인물이 한 파일에 합쳐진 이미지,
캐릭터까지 미리 그려진 장면 삽화는 기본 목록에서 숨긴다. 다만 기존 작품과
원작 자료의 호환성을 위해 파일을 삭제하지 않고 `모든 이미지`에서 고를 수
있게 보존한다. 추가 자료를 이미 사용 중인 장면에서 이미지 선택 창을 열면
현재 이미지를 찾을 수 있도록 자동으로 모든 이미지를 보여 준다.

카드와 결과 구역에는 `기본 추천` 또는 `추가 자료`, 캐릭터의 `전신`,
`상반신`, `여러 인물`을 표시한다. 작품·원작 사용 여부·분류 필터와
즐겨찾기·최근 사용 기능은 두 보기 범위에서 그대로 사용할 수 있다.

### 10.6 캐릭터 위치를 묶어서 적용

캐릭터 위치는 현재 장면의 이미지마다 따로 저장하지 않는다. 표정이나 동작
이미지가 바뀔 때 인물이 위아래로 들썩이는 일을 막기 위해 위치 묶음은 다음
세 분류 값으로 정한다.

`작품 + 인물 + 구도`

예를 들어 `토끼와 자라 + 토끼 + 전신`을 공유하는 토끼의 기본·기쁨·슬픔·
분노 이미지는 하나의 위치 묶음이다. 표정·동작 값은 위치 묶음의 기준에서
제외한다. 같은 인물이라도 `전신`과 `상반신`은 별도 묶음으로 다룬다.

적용 순서는 다음과 같다.

1. 자료별 투명 여백·바닥선 기본 보정
2. 작품 전체의 위치 묶음 설정
3. 필요한 경우 챕터 전체 예외

학생이 조정하는 값은 `크기: 작게·기본·크게`, `높이: 위로·기본·아래로`
정도로 제한한다. 조정하면 기본적으로 같은 위치 묶음의 모든 이미지에
적용된다고 알려 준다. `이 챕터에서만 다르게 배치`는 접힌 추가 설정으로
제공한다.

인물 배치 기능은 이미지 선택 창 안에 섞지 않는다. 이미지를 고른 뒤 현재
장면 편집 화면의 `인물 배치`를 펼쳐 조정한다.

1. `왼쪽 인물`과 `오른쪽 인물` 탭
2. 현재 위치 묶음 표시: `토끼와 자라 · 토끼 · 전신`
3. `높이`: 위로 / 기본 / 아래로
4. `크기`: 작게 / 기본 / 크게
5. 적용 범위 안내: `같은 묶음의 모든 이미지에 적용`
6. `이 챕터에서만 다르게 배치` 추가 설정
7. `묶음 기본값으로 되돌리기`

버튼은 3단계 분할 버튼으로 제공하며 슬라이더, 픽셀값, 드래그 손잡이는
사용하지 않는다. 값을 바꾸는 동안 작은 미리보기 또는 현재 무대에서 결과를
확인하되, 적용 범위 문구가 항상 함께 보여야 한다.

장면별 위치 예외와 픽셀 좌표·자유 드래그는 첫 버전에 넣지 않는다. 특별한
연출 때문에 후속 버전에서 장면 예외를 허용하더라도 `이 장면만 다른 위치`
표시와 `묶음 위치로 되돌리기`를 함께 제공한다. 배경의 초점 위치는 캐릭터
위치 묶음과 별도 규칙으로 다룬다.

## 11. 챕터와 장면

### 11.1 챕터

필수값:

- 고유 ID
- 재생 순서
- 챕터 제목
- 한 줄 줄거리

선택값:

- 기본 배경 이미지
- 왼쪽 기본 캐릭터 이미지
- 오른쪽 기본 캐릭터 이미지
- 챕터에서 사용할 화자 이름
- 챕터에서 사용할 캐릭터 이미지 목록
- 챕터에서 사용할 장소·배경 목록
- 챕터 역할·분위기·주요 사건·다음 내용 메모

첫 챕터에는 이미지가 없어도 대사만으로 플레이할 수 있다. 챕터를 삭제하면
소속 장면도 함께 삭제하므로 삭제 전에 영향 범위를 알려 준다.

### 11.2 장면

필수값:

- 고유 ID
- 소속 챕터 ID
- 챕터 안 순서
- 종류: 대사 또는 해설
- 내용

대사일 때:

- 화자 위치: 왼쪽 또는 오른쪽
- 화자 이름

선택값:

- 왼쪽 캐릭터 이미지
- 오른쪽 캐릭터 이미지
- 장면 배경
- 장면 역할·감정·연출 메모

선택 이미지를 비우면 챕터 기본값을 쓴다. 각 장면은 다른 장면의 선택을
이어받지 않는다. 중간 장면을 삭제하거나 순서를 바꿔도 뒤 장면의 이미지가
뜻밖에 바뀌지 않는다.

### 11.3 대본 전체

각 행에 다음을 둔다.

- 자동 장면 번호
- 대사·해설 선택
- 화자 위치
- 화자 이름
- 내용
- 사용 중인 이미지 요약
- 위로·아래로 이동
- 자세히 편집
- 복제·삭제

태블릿과 모바일에서는 내용 입력을 넓게 확보하고 나머지 조작을 접거나
아래로 배치한다.

### 11.4 다른 장면의 이미지 배치 가져오기

장면 꾸미기에서 작품 안의 다른 장면을 선택해 다음 세 값을 한 번에
가져올 수 있다.

- 배경 이미지
- 왼쪽 캐릭터 이미지
- 오른쪽 캐릭터 이미지

가져오기 전에 선택한 장면의 작은 미리보기와 이미지 이름을 보여 준다.
대사·해설, 화자 이름과 화자 위치는 현재 장면 값을 유지한다. 원본 장면이
챕터 기본 이미지를 사용한 경우에는 그 실제 이미지를 현재 장면 값으로
복사해, 이후 원본 챕터 설정이 바뀌어도 가져온 배치가 달라지지 않게 한다.

## 12. Excel·Google 시트 구조

Excel과 Google 시트용으로 서로 다른 양식을 유지하지 않는다. 공식
`공통 작품 양식` 하나가 다음 탭을 가진다.

- 기준 파일: `public/templates/놀퀴즈_스토리_템플릿.xlsx`
- Excel 사용: 파일을 직접 열어 편집
- Google 시트 사용: 같은 파일을 Google Drive에 올려 Google 시트로 열기
- 웹 사용: Excel 파일 또는 공개 Google 시트 주소로 불러오기

Google 시트로 변환해도 탭 이름과 헤더를 바꾸지 않는다. 시트별 꾸밈과
드롭다운은 달라질 수 있지만 웹이 읽는 실제 값과 구조는 같아야 한다.

- 놀퀴즈 저작권

### `장의 흐름`

| 열 | 의미 |
|---|---|
| 장 ID | 컷과 연결하는 고유값. 내부 값은 이전 호환을 위해 `chapter-*` 사용 가능 |
| 순서 | 재생 순서 |
| 장 제목 | 화면에 보이는 제목 |
| 이야기 단계 | 발단·전개·위기·절정·결말 중 하나 이상. 쉼표로 구분 |
| 한 줄 줄거리 | 편집 도움말 |
| 장의 역할·분위기 | 플레이에는 보이지 않는 편집용 창작 메모 |
| 꼭 들어갈 사건 | 장의 사건 메모 |
| 다음 장 아이디어 | 다음 내용 연결 메모 |

한 행이 한 장이다. 한 장에는 위기와 절정처럼 여러 이야기 단계가 함께 들어갈 수
있다. 이 표만 보아도 장별 사건과 앞뒤 연결을 검토할 수
있어야 한다. 실제 이미지와 화자 제한은 글 흐름을 가리지 않도록 다음
`장의 자료` 탭으로 분리한다.

### `장의 자료`

| 열 | 의미 |
|---|---|
| 장 ID | `장의 흐름`과 연결하는 고유값 |
| 배경 이미지 | 장 기본 배경 |
| 왼쪽 기본 이미지 | 왼쪽 캐릭터 기본값 |
| 오른쪽 기본 이미지 | 오른쪽 캐릭터 기본값 |
| 이 장의 화자 | 쉼표로 구분한 화자 이름 |
| 캐릭터 이미지 목록 | 쉼표로 구분한 장의 캐릭터 자료 |
| 장소·배경 목록 | 쉼표로 구분한 장의 배경 자료 |

`장의 흐름`과 `장의 자료`의 `장 ID`는 같아야 한다. 학생은 제목과
줄거리 검토에는 `장의 흐름`을, 컷에서 고를 자료를 제한할 때는
`장의 자료`를 사용한다.

### `창작 메모`

자유롭게 추가되는 항목 때문에 작품 탭의 열을 계속 늘리지 않는다. 한 행을
메모 안의 한 항목으로 사용하고 같은 `메모 ID`를 가진 행을 한 메모로 묶는다.

| 열 | 의미 |
|---|---|
| 메모 ID | 같은 메모의 여러 항목을 묶는 값 |
| 메모 종류 | 자유 메모, 인물, 관계, 장소·세계, 사건·갈등 |
| 메모 제목 | 학생이 붙인 제목 |
| 연결 장 ID·연결 컷 ID | 선택적인 참고 연결. 삭제된 대상을 가리켜도 불러오기를 막지 않음 |
| 항목 ID | 메모 안의 항목 고유값 |
| 항목 이름 | 기본·추천·직접 만든 항목 이름 |
| 내용 | 학생이 쓴 글. 긴 문장과 줄바꿈 허용 |
| 항목 종류 | 기본, 추천, 직접 추가 |
| 메모 순서·항목 순서 | 웹에서 보여 줄 순서 |

빈 항목도 행으로 보존한다. `창작 메모` 탭이 없는 이전 Excel과 Google
시트는 빈 메모 배열로 정상적으로 불러온다. 공개 Google 시트에서도 같은
탭과 열을 선택적으로 읽으며 웹에서 시트로 쓰거나 자동 동기화하지 않는다.

| 저작권 | 기본 제공 이미지 © 놀퀴즈 |

이미지 파일 자체를 Excel에 넣지 않는다. 웹이 알고 있는 이미지 ID와 이름을
저장해 파일 크기를 작게 유지한다.

새 양식은 `시작하기`, `이야기 구성`, `장의 흐름`, `장의 자료`, `화자`,
`컷 대본`, `창작 메모`, `리소스`를 사용한다. 웹은 이전에 저장한 `작품`,
`챕터`, `챕터 흐름`, `장면`, `대사` 탭도 계속 읽는다. 이전 파일을 웹에서 연 뒤
다시 `Excel로 저장`하면 새 8개 탭 구조로 옮겨진다.

## 13. 저장·백업·업데이트

### 13.1 브라우저 상태

기기에는 최소 세 상태를 둔다.

- `현재 편집본`: 입력할 때마다 자동 저장
- `직전 편집본`: 큰 불러오기나 플레이 반영 직전 백업
- `플레이 버전`: 마지막 반영 성공본

`방금 전으로 복구`는 직전 편집본이 있을 때만 활성화한다. 브라우저 데이터
삭제, 시크릿 모드, 기기 교체에는 로컬 기록이 유지되지 않으므로 중요한
작품은 `Excel로 저장`하도록 안내한다.

Excel 저장은 현재 편집본의 스냅숏을 새 파일로 만든다. 여러 시점의 파일을
보관해 이야기 버전으로 사용할 수 있게 기본 파일명에 작품 제목과 저장
시각을 포함한다. 학생이 직접 `1차`, `결말 수정`, `최종`처럼 이름을
바꾸어도 다시 불러올 수 있어야 한다.

다른 Excel 또는 Google 시트를 불러오기 직전에는 현재 편집본을
`직전 편집본`으로 백업한다. 불러온 뒤 문제가 있으면 `방금 전으로 복구`로
돌아갈 수 있게 한다.

### 13.2 플레이에 반영

`현재 편집을 플레이에 반영`을 누르면:

1. 현재 편집본을 직전 편집본으로 백업
2. 전체 필수값과 연결 확인
3. 새 플레이 버전 생성
4. 기기의 플레이 버전 교체
5. 완료 시각과 챕터·장면 수 표시

Google 시트 또는 Excel로 자동 저장하지 않는다.

업데이트 중에는 `강제 중지` 외의 편집, 탭 이동, 자료 불러오기, 플레이를
막는다. 완료·실패·중지가 확정된 뒤 조작을 다시 허용한다.

### 13.3 Excel·시트 불러오기

외부 자료는 한 번 읽고 웹 편집본으로 변환한다. 같은 자료를 확인 명목으로
두 번 읽지 않는다. 검사 항목:

- 필요한 탭과 열
- 챕터가 한 개 이상인지
- 장면의 챕터 ID가 실제 챕터와 연결되는지
- 종류와 화자 위치가 허용된 값인지
- 캐릭터 칸에 캐릭터 이미지가 있는지
- 배경 칸에 배경 이미지가 있는지
- 이미지 이름 또는 ID가 리소스에 있는지

오류는 `챕터 2 · 장면 3: 배경 칸에 캐릭터 이미지가 있어요`처럼 학생이
찾을 수 있는 위치와 고칠 방법을 함께 표시한다. 경고만 있는 자료는 불러온
뒤 문제 위치를 표시하고, 치명적 오류는 편집본 교체를 막는다.

### 13.4 통신 끊김과 강제 중지

- 진행 중 화면에 현재 단계 표시
- `업데이트 강제 중지`만 허용
- 네트워크 요청은 취소 가능하게 구성
- 편집본과 직전 플레이 버전 보존
- 중지 후 `직전 플레이는 그대로예요` 표시
- Google 통신이 없어도 로컬 편집·Excel 열기·플레이 가능

## 14. 이미지 규격과 표시

### 14.1 캐릭터

권장:

- 투명 PNG 또는 WebP
- 기본 제공 전신은 `800 × 1200`
- 알파 10% 이상인 발의 마지막 픽셀 `y=1149`와 하단 50px 투명 여백
- 일반적인 선 자세는 머리 또는 모자 몸체 위 120~180px 여백
- 몸통 시각 중심 `x=400` 기준 ±12px
- 한 파일 2MB 이하
- 캐릭터 둘레의 빈 투명 공간을 과도하게 두지 않음

학생이 외부에서 만든 이미지는 현재 MVP에 직접 추가하지 않는다. 후속
업로드 기능을 만들 때는 Canva 배경 제거 또는 손 지우개로 배경을 정리할 수
있음을 안내한다. 배경 제거 품질을 앱이 강제로 판정하지 않고 미리보기에서
사용자가 판단하게 한다.

기본 제공 전신 이미지는 `작품 + 인물 + 디자인 + 변형 + 구도`별 승인 기준본을
먼저 정한다. 같은 캐릭터의 감정·동작 Pose는 기준본의 얼굴, 체형, 의상, 색감과
머리/몸 비율을 유지한다. 캐릭터마다 기본 색감은 하나만 사용하며, 토끼 신규
감정 세트에는 현재 승인된 중간 회갈색 기준을 사용한다.

전체 알파 경계 상자의 높이를 기계적으로 같게 만들지는 않는다. 토끼 귀, 새우
더듬이, 용왕 뿔, 수염 끝, 펼친 손과 소품은 자세에 따라 움직일 수 있다. 대신
발선, 몸통 중심, 눈높이, 어깨·가슴선, 장식물을 제외한 머리 크기와 중심 신체
높이를 비교한다.

- 발선·좌우 위치만 다르면 평행이동한다.
- 전신이 같은 비율로 작거나 크고 머리/몸 비율이 같으면 발을 축으로 균일
  확대·축소한다.
- 머리/몸 비율, 얼굴 정체성, 팔다리 길이, 의상 구조 또는 화풍이 달라 부분
  변형이 필요하면 보정하지 않고 기준본을 넣어 재생성한다.
- 가로·세로를 다르게 늘리거나 머리만 따로 키우는 보정은 금지한다.

상세 허용 오차, 보정 전 백업, 반복 압축 방지와 Audit 판정은
`docs/decisions/character-pose-normalization-v1.md`를 따른다. 상반신 이미지는
머리 시작 높이를 같은 기준으로 맞춰 표정이 바뀌어도 위아래로 튀는 느낌을
줄인다. 플레이에서 말하지 않는 캐릭터를 어둡게 표시할 때는 크기를 바꾸지
않는다. 따라서 같은 이미지는 화자가 바뀌어도 글상자 위의 위치가 움직이지 않는다.

### 14.2 배경

권장:

- 16:9
- 1600×900 안팎
- JPG, PNG 또는 WebP
- 한 파일 3MB 이하
- 중요한 인물·글자·사물은 중앙 안전 영역에 배치

한 이미지를 모든 화면 크기에 사용하고 비율을 유지한 채 일부를 자른다.
권장 규격과 달라도 차단하지 않는다.

### 14.3 화질과 성능

초고화질을 요구하지 않는다. 무료 이미지 제작 도구에서도 만들 수 있는
크기를 기준으로 한다. 썸네일과 선택 창은 지연 로딩하고, 실제 장면에 필요한
이미지를 우선 표시한다.

## 19. 완료 판정

- Google 로그인 없이 빈 작품을 시작할 수 있다.

- 공개 Google 시트는 버튼을 눌렀을 때만 한 번 읽는다.
- 같은 공통 작품 양식을 Excel과 Google 시트에서 모두 사용할 수 있다.
- Google 시트를 불러온 뒤 원본과 자동 연결되지 않는다는 사실이 화면에 보인다.
- 외부 자료를 불러와도 플레이는 `플레이에 반영` 전까지 바뀌지 않는다.
- 새 화자를 다른 장면에서 다시 선택할 수 있다.
- 이미지를 바꿔도 화자 이름이 바뀌지 않는다.
- 캐릭터와 배경이 선택 화면에서 섞이지 않는다.
- 같은 분류의 여러 값은 그중 하나에 맞으면 나오고, 다른 분류를 추가하면
  모든 분류를 만족하는 결과로 좁아진다.
- 즐겨찾기와 최근 사용이 이 기기에 남는다.
- 이야기 구성과 장면 메모가 플레이 화면에는 나타나지 않는다.
- 자유 메모를 여러 개 만들고 인물·관계·장소·사건 도움 틀을 최소 항목부터 사용할 수 있다.
- 추천 항목과 직접 만든 항목을 추가하고 위·아래 이동하거나 삭제할 수 있다.
- 빈 창작 메모 항목도 저장을 막지 않으며 이전 브라우저 저장본이 정상적으로 열린다.
- 창작 메모가 Excel 저장·불러오기에서 긴 글, 빈 항목, 직접 만든 항목까지 왕복 보존된다.
- `창작 메모` 탭이 없는 이전 Excel과 공개 Google 시트도 정상적으로 열린다.
- 편집 중 전체 이야기·현재 챕터·현재 장면 메모를 화면 이동 없이 확인할 수 있다.
- 작품 전체의 챕터·장면 메모를 검색해 해당 기록으로 바로 이동할 수 있다.
- 데스크톱에서는 글 위에 창작 메모 팝업을 작게 또는 크게 띄울 수 있다.
- 태블릿·모바일에서는 창작 메모 팝업을 닫은 뒤 같은 장면으로 돌아올 수 있다.
- 작품·챕터·장면 버튼이 영향을 주는 내용 가까이에 일관되게 배치된다.
- 아이콘만 보고 뜻을 추측해야 하는 필수 버튼이 없다.
- 챕터 전체 화면에서 모든 글을 이어 읽고 즉시 수정할 수 있다.
- 현재 장면 화면의 글상자를 눌러 대사·해설을 직접 수정할 수 있다.
- 두 편집 화면을 오가도 선택 장면, 입력 내용과 스크롤 위치가 유지된다.
- 새 장면을 만들면 해당 글 입력칸에 바로 커서가 놓인다.
- 장면 선택 목록에는 현재 챕터에서 고른 화자·캐릭터·배경만 나타난다.
- 챕터의 모든 대사와 해설을 한 화면에서 순서대로 볼 수 있다.
- 대사는 `화자명: (행동) 대사`가 한 문단으로 이어지고, 해설은 서술 카드로 편집과 플레이에서 즉시 구분된다.
- 대사의 괄호 부분은 그대로 보이며 옅은 기울임꼴로 구분된다.
- 해설에 괄호가 있으면 장면 위치를 알려 주고 플레이 적용을 멈춘다.
- 장면 번호가 자동으로 이어지고 순서를 바꿀 수 있다.
- 업데이트 중 강제 중지 외의 조작이 막힌다.
- 처음부터와 원하는 챕터부터 플레이할 수 있다.
- 데스크톱·태블릿·모바일에서 핵심 편집과 플레이가 가능하다.
- 기본 제공 이미지 저작권이 웹과 Excel에 표시된다.
