# 이야기별 · 학생용 스토리게임 웹 상세 설계

- 문서 상태: MVP 구현 기준
- 버전: 5.2
- 기준일: 2026-07-25
- 대상: 초등 고학년을 사용성 기준으로 한 혼합 연령 학생
- 핵심 방식: 기기 안 웹 편집 + Excel 수동 교환 + 공개 Google 시트 불러오기 + 분리된 플레이 버전

## 1. 제품 정의

학생이 놀퀴즈의 `토끼와 자라`, `옹고집전` 이미지를 고르고 대사와 해설을
써서, 웹·태블릿·모바일에서 바로 플레이하는 선형 스토리게임 제작 도구다.

한 학생이 기기 한 대에서 만드는 흐름을 기본으로 한다. 모둠은 한 기기를
함께 보며 역할을 나누거나, Excel 또는 Google 시트 한 부를 번갈아 편집한 뒤
대표 기기에서 불러올 수 있다. 자체 회원가입, 작품 저장 서버, 여러 기기의
실시간 공동 편집은 첫 버전에 두지 않는다.

아이디어 발상과 모둠 역할 나누기는 활동지로도 지원한다. 웹에는 활동지를
대신하거나 옮겨 적을 수 있는 `스토리 구상` 화면을 둔다. 구상 내용은
편집자에게만 보이는 창작 메모이며, 학생이 직접 만든 실제 대사·해설·이미지만
플레이 화면에 나타난다.

## 2. 최우선 원칙

1. 짧은 안내만 보고 5분 안에 첫 플레이 가능한 챕터를 만든다.
2. 학생은 코드, 좌표, 파일 경로를 직접 입력하지 않는다.
3. 편집 화면과 플레이 화면을 분리한다.
4. 편집 중인 내용은 플레이에 자동 반영하지 않는다.
5. 웹 입력은 기기에 자동 저장하고, 외부 파일과의 교환은 버튼을 눌렀을 때만 한다.
6. 이미지 파일과 화자 이름은 서로 독립된 값으로 다룬다.
7. 이미지 규격은 권장하되 조금 어긋나도 사용을 막지 않는다.
8. 캐릭터와 배경을 분리하고, 학생 화면에서는 분류 용어를 `태그`로 통일한다.
9. 서버와 외부 API에 의존하지 않아도 핵심 편집과 플레이가 가능해야 한다.
10. 원본이 달라도 `불러오기 → 확인 → 플레이에 반영` 순서는 항상 같다.
11. 처음에는 글쓰기에 집중하고 이미지는 `보기 설정` 또는 선택 창을 열었을
    때만 크게 보여 준다.
12. 한 챕터에서 쓸 화자·캐릭터·장소를 먼저 좁혀, 장면 드롭다운이 과도하게
    길어지지 않게 한다.

## 3. 핵심 용어

| 용어 | 뜻 |
|---|---|
| 작품 | 학생이 만드는 스토리게임 한 편 |
| 화자 목록 | 작품에서 반복해서 선택할 글상자 이름 목록 |
| 챕터 | 같은 기본 장소와 등장인물 배치를 공유하는 이야기 묶음 |
| 장면 | 플레이할 때 한 번에 보이는 해설 또는 대사 한 컷 |
| 챕터 기본 이미지 | 장면에서 별도 선택하지 않았을 때 쓰는 이미지 |
| 장면 이미지 | 그 장면에서만 기본값 대신 쓰는 표정·동작·배경 |
| 편집본 | 학생이 지금 수정 중이며 기기에 자동 저장되는 최신 내용 |
| 플레이 버전 | 마지막으로 `플레이에 반영`에 성공한 내용 |
| 불러오기 | Excel 또는 Google 시트 내용을 웹 편집본으로 가져오는 작업 |
| Excel로 저장 | 현재 웹 편집본을 새 `.xlsx` 파일로 내려받는 작업 |
| 태그 | 이미지의 작품·인물·장소·표정·동작을 찾기 위한 한국어 단어 |
| 스토리 구상 | 이야기 나침반, 처음·가운데·끝, 챕터 흐름, 창작 메모 |
| 챕터 전체 편집 | 현재 챕터의 모든 장면 글을 순서대로 보는 편집 화면 |
| 현재 장면 편집 | 플레이와 비슷한 무대에서 한 장면의 글과 이미지를 고치는 화면 |
| 챕터 자료 | 해당 챕터의 드롭다운에만 보이도록 미리 고른 화자·캐릭터·배경 |
| 편집 전용 메모 | 창작을 돕지만 플레이에는 표시하지 않는 구상·감정·연출 기록 |

학생 화면에서는 `챕터 1 · 장면 1`을 사용한다. 장면은 대사뿐 아니라 해설과
이미지 중심 컷도 포함하기 때문이다. 장면 번호는 순서에 따라 자동으로 붙고
학생이 직접 관리하지 않는다.

## 4. 확정된 데이터 흐름

### 4.1 기기 안 웹 편집

```text
웹에서 편집
  → 기기에 자동 저장
  → 플레이에 반영
  → 플레이 버전 교체
  → 필요할 때 Excel로 저장
```

웹 편집 내용은 입력할 때마다 기기에 자동 저장한다. Excel 또는 Google
시트로 자동 전송하지 않는다. 다른 파일에 보관하려면 학생이 `Excel로 저장`을
누른다.

### 4.2 Excel 편집

```text
웹에서 Excel로 저장
  → Excel에서 여러 탭을 편집
  → 웹에서 Excel 파일 열기
  → 검사 결과 확인
  → 플레이에 반영
```

Excel 파일은 브라우저 안에서만 읽는다. 작품 파일을 이야기별 서버로
업로드하지 않는다. 외부에서 바꾼 파일은 자동 감지하지 않으므로 다시
`Excel 파일 열기`를 해야 한다.

### 4.3 Google 시트 편집

```text
공개 또는 웹에 게시한 Google 시트 편집
  → 웹에 주소 입력
  → 시트에서 불러오기
  → 검사 결과 확인
  → 플레이에 반영
```

MVP는 공개 또는 웹에 게시한 Google 시트를 버튼을 누를 때 한 번 읽는
단방향 불러오기를 지원한다. 실시간 감시, 자동 새로고침, 웹에서 시트로
저장은 하지 않는다.

비공개 시트는 사용자가 Google 시트에서 `.xlsx`로 내려받아 `Excel 파일
열기`로 가져온다. 이 방식은 이야기별용 Google 로그인 화면, 자체 OAuth
프로젝트, 사용자별 API 토큰을 요구하지 않는다.

### 4.4 충돌 원칙

- 웹 편집본과 Excel·시트 내용이 동시에 바뀌어도 자동 병합하지 않는다.
- 불러오기 전 현재 편집본은 자동 백업한다.
- 불러온 내용은 먼저 편집본이 되며 플레이 버전은 그대로 둔다.
- 학생이 내용을 확인한 뒤 `플레이에 반영`해야 실제 플레이가 바뀐다.
- 무엇이 최신인지 시간만으로 추측하지 않고, 학생의 마지막 버튼 선택을 따른다.

## 5. 창작 흐름

1. 활동지 또는 `스토리 구상`에서 주제와 처음·가운데·끝을 정한다.
2. `웹에서 새 작품`, `Excel 파일 열기`, `Google 시트 불러오기` 중 하나를 고른다.
3. 작품 제목과 소개를 정한다.
4. 챕터 구상에서 주요 내용, 역할, 감정 흐름, 꼭 들어갈 사건을 적는다.
5. 이 챕터에서 사용할 화자 이름, 캐릭터 이미지, 장소·배경을 먼저 고른다.
6. 장면을 추가한다.
7. `챕터 전체 편집`에서 장면 종류, 화자 위치, 화자 이름, 글을 이어 쓴다.
8. `현재 장면 편집`에서 빈 글상자 또는 기존 글상자에 직접 쓰고 이미지를 놓는다.
9. 다시 `챕터 전체 편집`으로 돌아와 대사와 해설 흐름을 확인한다.
10. `플레이에 반영`한다.
11. 처음부터 또는 원하는 챕터부터 플레이한다.
12. 다시 편집하고 같은 과정을 반복한다.

각 편집 탭은 자유롭게 오갈 수 있다. 입력을 잃지 않도록 탭 이동 전에
기기 저장을 끝내며, 탭 이동 자체는 플레이 버전을 바꾸지 않는다.

## 6. 시작 화면

제작 시작에 Google 로그인을 강제하지 않는다. 첫 화면은 다음 경로를 같은
수준의 선택지로 제공한다.

- `웹에서 새 작품`: 완전히 빈 작품을 기기에서 시작
- `Excel 파일 열기`: 이 기기의 `.xlsx` 작품을 열기
- `Google 시트 불러오기`: 공개 또는 웹에 게시한 시트 주소로 시작
- `저장된 작업 이어하기`: 이 기기에 편집본이 있을 때만 표시
- `예시 작품 플레이`: 로그인과 편집 없이 기본 작품 체험

`파일 업로드` 대신 `파일 열기`라고 표현한다. 파일이 외부 서버로 전송된다는
오해를 줄이기 위해 “이 기기 안에서만 읽어요”를 함께 표시한다.

완전히 빈 작품은 제목, 소개, 화자, 챕터, 장면을 비운다. 예시 작품을 빈
작품의 강제 원본으로 복제하지 않는다.

## 7. 편집 화면

### 7.1 상단 공통 영역

- 작품 제목
- 작품 소개
- 현재 챕터·장면 수
- `기기에 저장됨`, `저장 중`, `저장 실패` 상태
- 최근 플레이 반영 시각
- `처음부터 플레이`

### 7.2 작업 화면

1. `스토리 구상`
2. `이야기 만들기`
3. `플레이`

`이야기 만들기` 안에는 자유롭게 오갈 수 있는 두 편집 화면을 둔다.

- `챕터 전체 편집`: 현재 챕터의 모든 대사·해설을 연속 표시
- `현재 장면 편집`: 플레이와 닮은 무대에서 한 장면의 글·화자·이미지 수정

챕터 전체 편집은 하나의 큰 텍스트 상자가 아니다. 각 장면이 독립된 구조를
유지하며 종류, 화자, 위치, 내용, 순서를 바로 바꿀 수 있어야 한다.

두 화면 모두 `현재 편집 · 챕터 N · 장면 N`을 항상 표시한다. 데스크톱은
챕터 목록을 옆에 두고, 태블릿·모바일은 챕터 선택 드롭다운으로 바꾼다.

### 7.3 스토리 구상과 편집 전용 정보

스토리 구상 화면은 `전체 이야기 구성`과 `챕터 흐름 구성`으로 나눈다.

`전체 이야기 구성`에는 다음을 둔다.

- 이야기 나침반: 주인공, 바라는 것, 중심 문제, 마지막 변화
- 위 네 값을 이어 쓰는 한 줄 이야기
- 안내 질문이 있는 처음·가운데·끝
- 등장인물, 주제, 전체 분위기
- 아직 정하지 못한 것과 자유 창작 메모
- 제목·주인공·목표·문제·뼈대·챕터의 작성 여부를 보여 주는 구성 점검

구성 점검은 필수 검사나 완료 조건이 아니다. 학생이 막혔을 때 비어 있는
부분을 발견하는 안내판으로만 쓰며, 언제든 바로 장면 쓰기로 이동할 수 있다.

`챕터 흐름 구성`은 모든 챕터를 순서 카드로 보여 준다. 각 카드에서 주요
변화, 사건 수, 장면 수, 다음 챕터 연결을 확인하고 `구상 다듬기` 또는
`대사 쓰기`로 바로 이동한다. 챕터마다 전체 이야기에서 맡은 역할,
인물의 감정 변화, 꼭 일어날 사건, 다음을 궁금하게 만드는 연결을 기록한다.
챕터 대본 편집에서 `구상 메모 보기`를 열면 전체 이야기 나침반과 해당
챕터의 변화·역할·사건을 함께 보여 주어, 메모를 다시 찾으러 이동하지 않고
대사와 해설을 쓸 수 있게 한다.

장면에는 장면 역할, 감정 메모, 연출 메모를 둘 수 있다. 이 값들은
`편집할 때만 보는 내용`으로 명확히 표시하고 플레이 렌더링에서 제외한다.

### 7.4 챕터 자료 제한

각 챕터는 화자 이름, 캐릭터 이미지, 장소·배경 목록을 가진다. 장면의
드롭다운은 이 목록만 보여 준다. 필요한 자료가 없으면 `+ 자료 추가`를 눌러
전체 이미지 선택 창에서 태그·검색·즐겨찾기·최근 사용으로 찾는다.
자료를 고르는 것과 화자 이름을 정하는 것은 서로 독립이다.

### 7.5 자료 가져오기·내보내기

- `Excel 파일 열기`
- `Excel로 저장`
- Google 시트 주소
- `시트에서 불러오기`
- `빈 Excel 템플릿 받기`

자료 조작은 편집 탭과 분리된 한 영역에 모은다. Google 시트는 “공개 또는
웹에 게시한 시트만 가능”을 짧게 표시한다.

### 7.6 하단 업데이트 영역

화면 아래 고정 영역에는 `현재 편집을 플레이에 반영`을 둔다. 수정되지 않은
상태에서는 반영할 내용이 없음을 표시한다.

## 8. 플레이 화면

플레이 화면은 편집 도구를 숨기고 다음만 보여 준다.

- 작품 제목과 챕터 제목
- 배경
- 왼쪽 캐릭터
- 오른쪽 캐릭터
- 화자 이름
- 대사 또는 해설
- 이전·다음 장면
- 처음부터 시작
- 챕터 골라 시작
- 편집으로 돌아가기

배경은 같은 이미지 한 장을 데스크톱, 태블릿, 모바일에 사용한다. 화면을
채우기 위해 비율을 유지한 채 일부를 자르는 `cover` 방식을 기본으로 한다.

## 9. 화자 이름 설계

### 9.1 이미지와 이름 분리

캐릭터 이미지는 외형, 표정, 동작만 정한다. 글상자 화자 이름은 학생이
만든 이야기 속 이름이다.

| 선택한 이미지 | 글상자 화자 이름 | 결과 |
|---|---|---|
| `토끼_놀람.png` | `토끼` | 토끼 이미지와 토끼 이름 |
| `토끼_놀람.png` | `달토끼` | 같은 이미지에 달토끼 이름 |
| `토끼_놀람.png` | `민수` | 같은 이미지에 민수 이름 |

이미지를 바꿔도 화자 이름은 바뀌지 않는다. 이름을 바꿔도 이미지는 바뀌지
않는다.

### 9.2 재사용 화자 목록

1. 기존 이름을 드롭다운에서 고른다.
2. 없으면 `+ 화자 추가`로 만든다.
3. 새 이름은 현재 장면에 바로 선택된다.
4. 이후 다른 모든 대사 장면에서도 계속 고를 수 있다.

해설 장면은 화자 이름 대신 `해설`을 표시한다. 캐릭터 이미지를 골랐다는
이유로 화자 이름을 강제하지 않는다.

## 10. 이미지 도감과 선택

### 10.1 자료 구분

첫 단계에서 다음 두 종류를 명확히 나눈다.

- `캐릭터 이미지`
- `배경 이미지`

캐릭터 선택 칸에는 배경을, 배경 선택 칸에는 캐릭터를 넣을 수 없게 한다.

### 10.2 이미지 이름

학생이 이름만 보고도 대강 알 수 있게 `토끼_놀람.png`,
`자라_지침.png`, `용궁_환영연회장.png`처럼 표시한다. 원본 파일명이
어렵더라도 학생용 표시 이름은 한국어로 제공한다.

### 10.3 태그

학생 화면의 분류 용어는 `태그` 하나만 쓴다. 태그는 한국어로 제공한다.

예:

- 작품: `토끼와 자라`, `옹고집전`
- 인물: `토끼`, `자라`, `용왕`, `옹고집`
- 표정·동작: `기쁨`, `슬픔`, `분노`, `놀람`, `걱정`, `도망`
- 장소·장면: `마을`, `용궁`, `연회장`, `낮`, `밤`

태그를 여러 개 선택하면 모든 태그를 함께 가진 이미지만 남기는 AND
방식으로 결과를 좁힌다. 선택한 태그는 칩으로 보이고 하나씩 해제하거나
`모두 지우기`로 초기화할 수 있다.

### 10.4 찾기 편의

- 이름 검색
- 여러 태그 선택
- `즐겨찾기`
- `최근 사용`
- 썸네일 미리보기
- 결과 개수 표시

즐겨찾기와 최근 사용 기록은 작품 데이터가 아니라 해당 기기의 브라우저에
저장한다. 최근 사용은 가장 최근에 고른 순으로 제한된 개수만 유지한다.

### 10.5 이미지 선택

모든 이미지 입력은 두 방법을 함께 제공한다.

- 이름이 보이는 드롭다운
- `이미지 고르기`를 누른 썸네일 선택

장면별 선택에서는 `챕터 기본 이미지 사용`을 첫 항목으로 둔다. 이미지
썸네일은 창을 열었을 때 불러와 태블릿의 데이터와 메모리 사용을 줄인다.
기본 편집 화면은 `글만 보기`이며, `작은 그림 함께 보기`를 선택했을 때만
목록에 썸네일을 표시한다.

## 11. 챕터와 장면

### 11.1 챕터

필수값:

- 고유 ID
- 재생 순서
- 챕터 제목
- 한 줄 줄거리

선택값:

- 기본 배경 이미지
- 왼쪽 기본 캐릭터 이미지
- 오른쪽 기본 캐릭터 이미지
- 챕터에서 사용할 화자 이름
- 챕터에서 사용할 캐릭터 이미지 목록
- 챕터에서 사용할 장소·배경 목록
- 챕터 역할·분위기·주요 사건·다음 내용 메모

첫 챕터에는 이미지가 없어도 대사만으로 플레이할 수 있다. 챕터를 삭제하면
소속 장면도 함께 삭제하므로 삭제 전에 영향 범위를 알려 준다.

### 11.2 장면

필수값:

- 고유 ID
- 소속 챕터 ID
- 챕터 안 순서
- 종류: 대사 또는 해설
- 내용

대사일 때:

- 화자 위치: 왼쪽 또는 오른쪽
- 화자 이름

선택값:

- 왼쪽 캐릭터 이미지
- 오른쪽 캐릭터 이미지
- 장면 배경
- 장면 역할·감정·연출 메모

선택 이미지를 비우면 챕터 기본값을 쓴다. 각 장면은 다른 장면의 선택을
이어받지 않는다. 중간 장면을 삭제하거나 순서를 바꿔도 뒤 장면의 이미지가
뜻밖에 바뀌지 않는다.

### 11.3 챕터 전체 편집

각 행에 다음을 둔다.

- 자동 장면 번호
- 대사·해설 선택
- 화자 위치
- 화자 이름
- 내용
- 사용 중인 이미지 요약
- 위로·아래로 이동
- 자세히 편집
- 복제·삭제

태블릿과 모바일에서는 내용 입력을 넓게 확보하고 나머지 조작을 접거나
아래로 배치한다.

## 13. 저장·백업·업데이트

### 13.1 브라우저 상태

기기에는 최소 세 상태를 둔다.

- `현재 편집본`: 입력할 때마다 자동 저장
- `직전 편집본`: 큰 불러오기나 플레이 반영 직전 백업
- `플레이 버전`: 마지막 반영 성공본

`방금 전으로 복구`는 직전 편집본이 있을 때만 활성화한다. 브라우저 데이터
삭제, 시크릿 모드, 기기 교체에는 로컬 기록이 유지되지 않으므로 중요한
작품은 `Excel로 저장`하도록 안내한다.

### 13.2 플레이에 반영

`현재 편집을 플레이에 반영`을 누르면:

1. 현재 편집본을 직전 편집본으로 백업
2. 전체 필수값과 연결 확인
3. 새 플레이 버전 생성
4. 기기의 플레이 버전 교체
5. 완료 시각과 챕터·장면 수 표시

Google 시트 또는 Excel로 자동 저장하지 않는다.

업데이트 중에는 `강제 중지` 외의 편집, 탭 이동, 자료 불러오기, 플레이를
막는다. 완료·실패·중지가 확정된 뒤 조작을 다시 허용한다.

### 13.3 Excel·시트 불러오기

외부 자료는 한 번 읽고 웹 편집본으로 변환한다. 같은 자료를 확인 명목으로
두 번 읽지 않는다. 검사 항목:

- 필요한 탭과 열
- 챕터가 한 개 이상인지
- 장면의 챕터 ID가 실제 챕터와 연결되는지
- 종류와 화자 위치가 허용된 값인지
- 캐릭터 칸에 캐릭터 이미지가 있는지
- 배경 칸에 배경 이미지가 있는지
- 이미지 이름 또는 ID가 리소스에 있는지

오류는 `챕터 2 · 장면 3: 배경 칸에 캐릭터 이미지가 있어요`처럼 학생이
찾을 수 있는 위치와 고칠 방법을 함께 표시한다. 경고만 있는 자료는 불러온
뒤 문제 위치를 표시하고, 치명적 오류는 편집본 교체를 막는다.

### 13.4 통신 끊김과 강제 중지

- 진행 중 화면에 현재 단계 표시
- `업데이트 강제 중지`만 허용
- 네트워크 요청은 취소 가능하게 구성
- 편집본과 직전 플레이 버전 보존
- 중지 후 `직전 플레이는 그대로예요` 표시
- Google 통신이 없어도 로컬 편집·Excel 열기·플레이 가능

## 14. 이미지 규격과 표시

### 14.1 캐릭터

권장:

- 투명 PNG 또는 WebP
- 세로형 전신 또는 반신
- 720×900 안팎
- 한 파일 2MB 이하
- 캐릭터 둘레의 빈 투명 공간을 과도하게 두지 않음

학생이 외부에서 만든 이미지는 현재 MVP에 직접 추가하지 않는다. 후속
업로드 기능을 만들 때는 Canva 배경 제거 또는 손 지우개로 배경을 정리할 수
있음을 안내한다. 배경 제거 품질을 앱이 강제로 판정하지 않고 미리보기에서
사용자가 판단하게 한다.

### 14.2 배경

권장:

- 16:9
- 1600×900 안팎
- JPG, PNG 또는 WebP
- 한 파일 3MB 이하
- 중요한 인물·글자·사물은 중앙 안전 영역에 배치

한 이미지를 모든 화면 크기에 사용하고 비율을 유지한 채 일부를 자른다.
권장 규격과 달라도 차단하지 않는다.

### 14.3 화질과 성능

초고화질을 요구하지 않는다. 무료 이미지 제작 도구에서도 만들 수 있는
크기를 기준으로 한다. 썸네일과 선택 창은 지연 로딩하고, 실제 장면에 필요한
이미지를 우선 표시한다.

## 19. 완료 판정

- Google 로그인 없이 빈 작품을 시작할 수 있다.
- 웹에서 수정한 내용이 새로고침 후에도 이 기기에 남는다.
- Excel로 저장한 작품을 다시 열어 같은 챕터와 장면을 복원할 수 있다.
- 공개 Google 시트는 버튼을 눌렀을 때만 한 번 읽는다.
- 외부 자료를 불러와도 플레이는 `플레이에 반영` 전까지 바뀌지 않는다.
- 새 화자를 다른 장면에서 다시 선택할 수 있다.
- 이미지를 바꿔도 화자 이름이 바뀌지 않는다.
- 캐릭터와 배경이 선택 화면에서 섞이지 않는다.
- 여러 한국어 태그를 고를수록 이미지 결과가 좁아진다.
- 즐겨찾기와 최근 사용이 이 기기에 남는다.
- 스토리 구상과 장면 메모가 플레이 화면에는 나타나지 않는다.
- 장면 선택 목록에는 현재 챕터에서 고른 화자·캐릭터·배경만 나타난다.
- 챕터의 모든 대사와 해설을 한 화면에서 순서대로 볼 수 있다.
- 장면 번호가 자동으로 이어지고 순서를 바꿀 수 있다.
- 업데이트 중 강제 중지 외의 조작이 막힌다.
- 처음부터와 원하는 챕터부터 플레이할 수 있다.
- 데스크톱·태블릿·모바일에서 핵심 편집과 플레이가 가능하다.
- 기본 제공 이미지 저작권이 웹과 Excel에 표시된다.
