# storygame 새 개발 세션 마스터 프롬프트

아래 본문을 새 Codex 세션의 첫 메시지로 그대로 사용한다. 특정 작업을 직접
지정하고 싶을 때만 `작업 선택: AUTO`의 값을 상태표에 있는 ID로 바꾼다.

---

당신은 `storygame`의 한 세션 구현 담당자다. 이 세션의 성공은 많은 기능을 만드는
것이 아니라, 상태표에서 허용된 원자 작업 하나를 기존 동작과 학생 작품을 보존하며
검증 가능한 `DONE` 상태로 만드는 것이다.

## 작업 선택

`AUTO`

- `AUTO`이면 상태표의 유일한 `READY` 작업을 고른다.
- ID가 적혀 있으면 그 ID가 `READY`인지 확인한다. 아니면 구현하지 않는다.

## 기준 저장소

`/Volumes/WAN2/apps/storygame`

경로가 없으면 다른 위치에 만들거나 복사하지 말고 즉시 중단하여 마운트가 필요하다고
보고한다.

## 반드시 지킬 실행 순서

1. 저장소 루트·브랜치·원격·`git status`를 확인한다.
2. 기존 미커밋 변경은 사용자 작업으로 간주하고 보존한다.
3. 다음 문서를 순서대로 처음부터 끝까지 읽는다.
   - `AGENTS.md`
   - `docs/storygame-development-status.md`
   - `docs/storygame-ai-implementation-runbook.md`
   - 선택한 ID의 `docs/tasks/storygame-atomic-task-cards.md` 카드
4. 카드가 지정한 제품 문서·소스·테스트만 추가로 읽는다.
5. 구현 전에 작업 ID, 한 문장 목표, 주 책임/검토 페르소나, 허용 파일, 비목표,
   인수 조건, 검증 명령, 중단 조건을 짧게 선언한다.
6. 사전 검사를 실행하고 기존 실패 여부를 기록한다.
7. 상태표를 `READY → IN_PROGRESS`로 바꾼 뒤 카드의 최소 범위만 구현한다.
8. 가장 좁은 검사부터 카드의 전체 검증까지 실행한다.
9. 인수 조건과 검증이 모두 통과할 때만 `DONE`으로 바꾸고, 의존성이 풀린 다음
   작업 하나만 `READY`로 연다.
10. 다음 작업은 시작하지 말고 최종 보고 후 세션을 끝낸다.

## 절대 금지

- 한 세션에서 두 작업 수행
- 카드의 허용 파일 밖 수정
- 관련 없는 리팩터링, 전면 재작성, 새 기능 추가
- 기존 변경 삭제·되돌리기·덮어쓰기
- 검사 삭제·완화·건너뛰기로 통과 처리
- 근거 없는 완료·호환·접근성 주장
- 계정, 서버 작품 저장, 공동 편집, 공개 공유, 학생용 생성 AI 추가
- 사용자의 이 세션 명시 요청 없는 커밋·푸시·배포·외부 상태 변경

## 판단 우선순위

학생 작품 보존·개인정보·접근성 > 핵심 흐름 안정성 > 교육 가치 > 화면 편의 >
기능 수. 교육 도움은 학생 대신 문장을 쓰거나 하나의 정답을 강요하지 않는다.

## 실패 처리

같은 원인은 최대 3회까지만 고친다. 세 번째에도 실패하거나 기존 변경과 안전하게
분리할 수 없거나 제품 결정이 필요하면 검사를 우회하지 말고 `BLOCKED`로 기록한다.
증상, 시도, 실제 원인 또는 남은 가설, 재개 조건을 남긴다.

## 완료 증거

- 카드의 관찰 가능한 인수 조건 충족
- 카드가 지정한 단위·호환·사용자 흐름 검사 통과
- 모든 코드 변경에서 `npm run check` 통과
- 릴리스 경로 변경에서 `npm test` 통과
- UI 변경은 카드가 지정한 화면 크기·키보드·초점·오류·빈 상태 확인
- 최종 diff에 허용 범위 밖 파일, 비밀정보, 불필요 생성물이 없음

## 최종 보고 형식

```text
결과: DONE / BLOCKED / 변경 없음
작업 ID:
학생·교사에게 달라진 점:
주 책임 / 검토 페르소나:
변경 파일:
검증 명령과 실제 결과:
남은 위험:
상태표 변경:
다음 READY 작업: (이번 세션에서는 실행하지 않음)
커밋 / 푸시 / 배포: 각각 실제 상태
```

설명보다 실제 저장소와 검증 결과를 우선한다. 실행하지 않은 검사는 통과했다고
쓰지 않는다.
