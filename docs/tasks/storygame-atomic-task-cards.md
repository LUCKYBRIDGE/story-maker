## OPS-02 — 저장소 구조·문서·의존성 정리

- 의존성: 사용자 직접 요청
- 가치: 현재 제품 경계와 맞지 않는 실험 구조를 없애고 다음 작업이 최신 문서와
  최소 의존성에서 시작되게 한다.
- 주 책임 / 검토: 프런트엔드 아키텍트 / 데이터 신뢰성, QA·릴리스 책임자
- 허용 파일: 미사용 D1·인증·시작 템플릿, 빌드 설정, 패키지, README,
  아키텍처·QA·현황·실행 문서, 무시된 로컬 작업 폴더
- 금지: 기존 `asset.id`·파일명·StoryProject 참조 변경, 서비스 캐릭터 삭제,
  사용자 구현 변경 초기화, 공개 배포
- 구현:
  1. import·빌드·문서 참조를 조사해 삭제 가능 대상을 증명한다.
  2. 사용하지 않는 Drizzle/D1/인증 예제와 기본 아이콘, 중복 보관 문서를 제거한다.
  3. 캐릭터 후보·검토표·미사용 초안을 후보/검토/보관 구조로 나눈다.
  4. 장·컷 용어, 공식 8개 Excel 탭, 9개 핵심 흐름과 실제 QA 증거 범위를 맞춘다.
  5. 비파괴 패치 범위에서 의존성 보안 경고를 줄이고 전체 회귀를 확인한다.
- 인수 조건:
  - 앱의 로컬 저장·Excel·플레이 경로와 모든 정식 자산 ID가 보존된다.
  - 미사용 서버 실험 코드가 빌드와 문서에서 제거된다.
  - 실제 학생 파일럿이 아닌 결과를 실제 관찰 성과로 주장하지 않는다.
  - `npm run check`, `npm test`, 프로덕션 의존성 감사와 문서 링크 검사가 통과한다.
- 완료 상태: 이 작업은 직접 유지보수 요청이므로 기존 유일한 `READY`인 A1-01을
  바꾸지 않고 `DONE` 기록만 추가한다.

## G0-01 — 작품 fixture 기반 고정

- 의존성: `OPS-01`
- 가치: 이전 작품과 손상 작품을 재현 가능하게 만들어 이후 저장 변경의 데이터
  손실을 막는다.
- 주 책임 / 검토: QA·릴리스 책임자 / 데이터 신뢰성 엔지니어
- 허용 파일: `package.json`, `tests/fixtures/story-projects.mjs`,
  `tests/story-project-fixtures.test.mjs`, 상태표
- 금지: `app/**`, Excel 원본·생성기, UI, 저장 키 변경, 새 의존성
- 사전 검사: `npm run check`; 허용 파일의 기존 diff 확인
- 구현:
  1. 현재 `StoryProject` 필드를 모두 가진 작고 고정된 v1 작품 fixture를 만든다.
  2. 정상본, `creativeMemos`가 없는 이전본, 중복 line ID, 없는 chapter를 참조하는
     line, 파싱 불가능 JSON 문자열을 각각 이름 붙여 제공한다.
  3. fixture를 매번 깊은 복사로 얻어 검사 간 변이를 막는다.
  4. fixture 자체의 정상·손상 특징과 고정 ID를 검사한다.
  5. `npm test`가 `tests/*.test.mjs` 전체를 실행하게 기존 스크립트만 최소 수정한다.
- 인수 조건:
  - 시간·무작위 값 없이 매번 같은 데이터가 나온다.
  - 각 손상 fixture는 의도한 결함 하나만 가진다.
  - 기존 5개 검사가 그대로 통과하고 새 fixture 검사가 추가된다.
  - 프로덕션 동작은 바뀌지 않는다.
- 검증: `node --test tests/story-project-fixtures.test.mjs`, `npm run check`, `npm test`
- 중단: 현재 타입만으로 정상 fixture를 판정할 수 없거나 허용 파일의 기존 변경과
  충돌하면 `BLOCKED`로 기록한다.
- 완료 상태: `G0-01 → DONE`, `G0-02 → READY`; 다른 작업은 시작하지 않는다.

## U1 공통 실행 계약

- U1은 화면 정합화 프로그램이다. 아래 카드는 한 세션에 하나만 수행한다.
- 주 책임/검토는 품질 관점이다. 실제 사람·다른 에이전트가 검토했다는 의미가 아니다.
- 모든 카드의 공통 허용 문서: 개발 상태표, 해당 원자 카드, 완성 실행 계획의
  해당 진행 기록, 관련 QA 실행 증거. 이 밖의 허용 파일은 카드별로 지정한다.
- 신규로 표시한 파일은 아직 없으며 해당 카드에서 필요성을 확인한 뒤 만든다.
  파일명이 현 코드와 달라졌다면 조용히 범위를 넓히지 말고 카드를 먼저 갱신한다.
- 공통 금지: 관련 없는 사용자 변경 수정, StoryProject/Excel 스키마 변경,
  기존 ID 교체, 캐릭터 재생성, 인증·클라우드·분기·업로드·새 의존성·공개 배포.
- UI 코드 변경은 아래 좁은 검사 뒤 `npm run check`, `npm test`를 실행한다.
  `npm test`가 빌드 후 렌더 검사까지 실행하므로 별도 빌드 통과로 대체하지 않는다.
- 실화면은 테스트용 프로필에서 `npm run dev -- --port 3001`로 실행해 확인한다.
  포트가 사용 중이면 해당 프로세스를 종료하지 말고 테스트용 다른 포트를 기록한다.
- 소스 문자열·정적 HTML 검사는 실제 클릭/입력 검수를 대신하지 않는다.
  조작 테스트 도구는 기존 사용 가능한 브라우저 수단을 우선하며 임의 의존성을 추가하지 않는다.
- 공통 되돌리기: 사전 diff/작업별 스냅숏과 비교해 **이번 카드 변경만** 복원한다.
  저장본·사용자 변경을 git reset/checkout으로 되돌리지 않는다.
- 다음 상태는 상태표에서만 결정한다. 검증 실패는 원인과 재개 조건을 남기고 BLOCKED,
  전부 통과하면 DONE. 다음 카드가 준비됐을 때만 READY로 열고 세션을 종료한다.

- 중단: 고정 말풍선 높이·과도한 글자 축소로 넘침을 숨기지 않는다. 원작 배포 번들을 소스에 복사하지 않는다.
- 되돌리기: 공통 되돌리기 적용; 사용자 작품·기존 미커밋 변경을 보존한다.
- 상태표: 모두 통과 시 U1-10 DONE. U1-11의 카드/선행 조건 확인 후 하나만 READY. 같은 세션에서 다음 작업은 하지 않는다.

- 선행: U1-10

1. CF-01~13 각각 실행 결과·환경·미실행 이유가 있음
