- 기준일: 2026-09-04
- 대상: 로그인 없이 기기에서 작품을 만들고 Excel로 보관하는 Story Maker
- 현재 자동 검사: `tests/core-user-flows.test.mjs`의 CF-01~CF-09
- 추가 계획: CF-10~CF-13은 U1 작업에서 구현·검증할 예정이며 아직 자동화/실행하지 않음
- 수동 검토: 실제 다운로드, 키보드 초점, 시각 배치와 모바일 소프트 키보드

실제 학생 작품·계정·비공개 시트를 사용하지 않는다. 수동 검토는 사이트 데이터가
비어 있는 테스트 프로필에서 실행하며, 실패 화면에는 학생 이름·본문·URL을 남기지
않는다. 캡처가 필요하면 `docs/qa/evidence/<ID>-<날짜>-<설명>.png`에 둔다.

## 공통 판정 기준

- 편집본을 고친 것만으로 플레이 버전이 바뀌면 실패다.
- 가져오기 실패가 현재 편집본·플레이본을 덮어쓰면 실패다.
- `장`, `컷`이 학생용 표준 용어다. `chapter-*`, `scene-*`는 호환용 내부 ID다.
- 장·컷·메모 왕복 뒤 안정 ID 기준으로 작업 위치가 복구되어야 한다.
- 주요 터치 목표는 44px 이상이고 키보드 포커스가 보여야 한다.
- 자동 검사 통과는 실제 브라우저 다운로드나 모바일 키보드 검증을 대신하지 않는다.

## CF-01 — 빈 작품에서 첫 플레이

1. `새 작품 만들기`에서 제목과 첫 장을 만든다.
2. `대본·컷 쓰기`에서 대사 컷을 추가하고 화자와 본문을 입력한다.
3. `플레이에 적용`한 뒤 플레이를 연다.

기대: 새 컷 본문에 초점이 보이고 자동 저장 상태가 갱신된다. 적용 뒤에만 제목과
대사가 플레이에 보이며 구상·창작 메모는 보이지 않는다.

## CF-02 — 이어쓰기와 플레이 분리

1. `토끼와 자라` 이어쓰기 템플릿을 연다.
2. 안내된 첫 빈 컷에 문장을 쓰고, 적용 전에 플레이를 확인한다.
3. 편집으로 돌아와 적용한 뒤 다시 플레이한다.

기대: 준비된 앞이야기와 편집 위치가 유지되고, 새 문장은 적용 전에는 보이지 않으며
적용 뒤에만 순서대로 보인다.

## CF-03 — 창작 메모 왕복

1. 편집 중인 장·컷을 기록하고 창작 메모를 연다.
2. 사건·갈등 도움 틀로 메모를 만들고 검색·수정한다.
3. 메모를 닫고 플레이를 확인한다.

기대: 같은 장·컷과 스크롤 위치로 돌아오고 Dialog 초점은 열었던 조작으로 복귀한다.
메모는 저장되지만 플레이에는 보이지 않는다.

## CF-04 — Excel 저장·다시 불러오기

1. 제목, 여러 단계가 연결된 장, 컷, 창작 메모가 있는 작품을 Excel로 저장한다.
2. 별도 테스트 프로필에서 파일을 선택하고 미리보기를 확인해 연다.
3. 이야기 구성, 장의 흐름·자료, 컷 대본, 창작 메모를 비교한다.

기대: 공식 8개 탭을 거쳐 공백·줄바꿈·연결 ID·이야기 단계가 보존된다. 가져온
편집본은 명시적 적용 전 플레이본을 조용히 바꾸지 않는다.

## CF-05 — 잘못된 파일 뒤 작품 보호

1. 적용된 테스트 작품에서 빈 파일 또는 손상된 `.xlsx`를 선택한다.
2. 오류 위치와 고치는 법을 확인하고 현재 편집·플레이를 다시 연다.

기대: 탭·행·열·잘못된 값을 포함한 안내가 보이고 해당 입력으로 이동할 수 있다.
현재 편집본과 플레이본은 그대로다.

## CF-06 — 새로고침 뒤 기기 저장 복원

1. 제목·장·대사 컷을 만든 뒤 `기기에 저장됨`을 확인한다.
2. 새로고침 후 `이 기기의 저장된 작업 이어하기`를 누른다.

기대: 버전 문서 봉투에서 본문이 복원된다. 마지막 장·컷의 재접속 복원은
현재 코드에서 별도 저장을 확인하지 못했으므로 U1-02에서 추가 검증할 목표다.
기존 CF-06 자동 검사 통과만으로 위치 복원까지 통과했다고 판단하지 않는다. 브라우저 데이터
삭제·시크릿 모드·기기 교체는 복구 범위가 아니며 Excel 보관 안내가 보인다.

## CF-07 — 모바일 글쓰기·메모·플레이

1. 390×844에서 컷 본문을 두 문장 이상 입력하고 실제 소프트 키보드를 연다.
2. 창작 메모를 쓰고 닫은 뒤 컷을 추가·적용한다.
3. 긴 대사를 플레이에서 읽고 앞뒤 이동한다.

기대: 입력칸과 주요 조작이 키보드에 가려지지 않고, 44px 터치 목표가 겹치지 않는다.
긴 글은 말풍선 영역에서 읽을 수 있으며 다음 컷 조작이 가능하다.

## CF-08 — 한 장의 여러 이야기 단계

1. 5단계 구성에서 한 장에 `위기`, `절정`을 함께 연결한다.
2. 장-단계 흐름표, 대본, 컷 꾸미기, 메모에서 라벨을 확인한다.
3. 4단계와 3단계로 바꿨다가 5단계로 돌아온다.

기대: 한 장의 여러 단계가 동시에 표시된다. 현재 구조에 없는 연결은 숨겨져도 데이터는
보존되며, 돌아왔을 때 복구된다. 미연결 장은 강제 오류가 아닌 성찰 안내로 보인다.

## CF-09 — 여러 단계의 Excel 왕복

1. 여러 단계가 연결된 작품을 Excel로 저장한다.
2. `장의 흐름`의 `이야기 단계` 셀을 확인하고 다시 불러온다.
3. 미리보기 뒤 편집본으로 열어 적용·플레이한다.

기대: 쉼표·가운뎃점·줄바꿈 형식을 읽고 표준 쉼표 형식으로 내보낸다. 알 수 없는
단계는 위치와 고치는 법을 안내하고, 유효한 다중 단계 순서와 플레이는 보존된다.

### CF-10 — 메인에서 새 작업/이어만들기

1. 테스트 전용 프로필의 저장본 없음·있음·손상·저장 거부 상태를 각각 준비한다.
2. 새 이야기→빈 작품/세 템플릿, 이어만들기→로컬/Excel/공개 시트 경로를 확인한다.
3. 기존 작업 교체를 취소하고, 잘못된 파일·같은 파일 재선택·파일 대화상자 취소를 확인한다.
4. 현재 draft/active/체크포인트와 저장 안내를 비교한다.

기대: A안 문구와 두 진입 유지, 실패/취소 뒤 기존 작품 불변, 성공한 교체만 새 작품으로
이동. 읽기 완료 전 예시를 저장 작품으로 표시하지 않음. 계정 요구·자동 동기화 없음.
1440×900, 1024×768, 390×844에서 실행한다.

### CF-11 — 구성·장·단계·Excel 보존

1. 장0/1/5/20 작품에서 제목·summary·theme·premise와 접힌 모든 계획 필드를 수정한다.
2. 3장에 위기+절정,4장에 절정을 연결하고 구조를5→3→4→5로 바꾼다.
3. 3장을 위/아래로 이동하고 해당 장 대본을 쓴 뒤 구성으로 돌아온다.
4. 장 기본 배경과 특정 컷 배경을 다르게 정하고 후보를 추가한다.
5. Excel 저장/재가져오기로 장/컷/메모 ID와 숨긴 필드를 비교한다.

기대: 목록 하나, 안정 ID·선택 유지, 다중 연결 복구, 단계로 순서를 강제하지 않음.
후보 추가/기본 변경/컷 override는 독립. 장0은 명시적으로 첫 장 추가, 5개 강제 없음.
1440×900, 820×1180, 390×844에서 실행한다.

### CF-12 — 플레이와 두 복귀 의미

1. 편집에서2컷을 선택하고 플레이를 열어5컷까지 이동한다.
2. 편집으로 돌아가기를 눌러2컷·원래 보기로 복귀하는지 확인한다.
3. 다시5컷을 재생하고 이 컷 고치기를 눌러5컷 ID로 편집하는지 확인한다.
4. 적용 이후 삭제한 컷/다른 작품/빈 작품/잘못된 index로 반복한다.
5. 메인에서 예시 플레이를 열고 닫은 뒤 학생 active와 draft가 그대로인지 확인한다.
6. 버튼·장 선택기에 초점을 둔 Enter/Space가 의도하지 않은 다음 컷 이동을 하지 않는지 확인한다.

기대: 순번 대신 안정 ID로 동작하고 사라진 컷은 안전한 안내. 예시가 저장 작품을 교체하지 않음.
1440×900, 390×844에서 실행한다.

### CF-13 — 작은 화면·긴 글·이미지·입력 위치

1. 같은 작품·컷을 기준으로 아래 모든 크기에서 대본→컷→표정 선택→취소/적용→대본 왕복.
2. 한글 조합·줄바꿈·선택 영역이 있는 입력 중 폭/높이를 바꾸고 소프트 키보드를 연다.
3. 1000자 대사/해설·무공백 글·200컷 작품·긴 장 제목을 입력·플레이한다.
4. 좌우 인물의 전신·반전·발선, 없는 자산·로드 실패를 확인한다.
5. 200% 글자 확대, 키보드만 탐색, 안전 영역과 조작 크기를 확인한다.

기대: 입력·선택·현재 위치 유지, 긴 글 끝까지 읽기와 다음 조작 가능, 주 조작44px,
전신 비율 보존. 키보드 개방 시 불필요한 고정 바와 무대가 입력을 가리지 않음.

크기: 1440×900, 1280×720, 1024×768, 820×1180, 390×844, 844×390,
추가320px. iOS/Android 실제 키보드는 모의 뷰포트와 별도 결과로 기록한다.
200컷 입력/보기 전환의 전후 비용을 같은 기기·브라우저에서 비교하고 입력 유실은 즉시 실패다.
학생·교사 수업 관찰은 내부 QA와 분리한다.
