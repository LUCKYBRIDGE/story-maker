| 확인 | 결과 | 증명하지 못하는 것 |

이전 시도의 스튜디오 브라우저 정책 및 배율·합성 문제는 격리된 Chrome 프로필과
페이지 표면 캡처로 해소했다. 캡처 PNG의 실제 픽셀 치수와 같은 시점의
`innerWidth`, `innerHeight`, `scrollWidth`를 대조했다. 테스트 템플릿과 빈 작품만
사용했고 학생의 기존 작품은 열거나 수정하지 않았다. 서비스 소스 변경은 없다.
원작 정적 파일만 서빙하면 이야기 API가 없어 실패한다. 정식 서버는 빌드 산출물의
`/ifstory/` 경로를 사용한다. 이전 `/games/ifstory/` 404와 브라우저 오류 표시는
영구적인 접근 제한의 증거가 아니었다. 확인된 서비스 경로로 정상 진입했다.

### 원작 실행 문제 해결과 비교 결과

- 원인1: 소스 디렉터리 경로를 서비스 경로로 사용했다. `scripts/build.mjs`는

- 원인2: 로컬에서 STORY_SESSION_SECRET가 없으면 이야기 시작 API가503을 반환한다.
  원작 `tests/story-api.test.mjs`의 공개 테스트 전용 값을 실행 인수에만 제공했다.
  실제 비밀값을 읽거나 원작 소스·배포 설정·자격 증명을 수정하지 않았다.
- 재현: 원작 저장소에서 `npm run preview -- --local --port 3003 --var
  STORY_SESSION_SECRET:test-only-story-session-secret-with-more-than-32-characters`.
  브라우저에서 `http://localhost:3003/ifstory/`를 연다. 이 값은 로컬 테스트 전용이며
  배포에 사용하면 안 된다.
- 토끼와 자라: 시작→기본 이름 자라→용궁 대청 첫 해설→다음 문장 이동 성공.

## 2. 재확인한 소스 차이

| 소스·경로 | 현재 사실 | 구현 계약/담당 |

## 3. 채택 배치와 구현 시작 치수 — 새 UI 실측 검증은 후속 카드

2026-09-04 사용자가 최적안 선택을 위임하여 01안을 채택했다. 별도 재승인 대기는
없다. 같은 장 상세를 재배치하며 별도 작성 페이지나 5개 보기 모드를 만들지 않는다.
04의 첫 행동 안내·05의 선택 장 중심 배치를 차용한다. 현행 모바일 구성의 긴
문서 높이를 줄이기 위해 핵심 필드 우선·자세한 계획 접기를 적용한다. 아래 값은
구현 시작 기준이지 아직 만들지 않은 목표 UI의 실측값이 아니다.

| 조건 | 구성 시작안 | 주 스크롤·초점 정책 |
|---|---|---|
| 가용 폭 ≥1200px | 바깥24px, 목록280~360px, 간격24px, 상세 minmax(0,1fr) | 문서 흐름을 기본. 목록20개에서만 독립 목록 스크롤 검토 |
| 800~1199px | 바깥20px, 장 목록은 펼치기/접기, 상세 폭 우선 | 목록 닫힘 뒤 선택 장 제목으로 초점 복귀 |
| <800px | 바깥16px, 장 선택기+선택 상세 한 열 | 전체 페이지 가로 넘침 금지, 선택 장의 현재 입력 유지 |
| 낮은 높이·가로 화면 | 설명과 보조 헤더 축소, 편집 무대 접기 허용 | 입력을 고정 바가 덮지 않음. 플레이 본문과 이동은 계속 노출 |
| 키보드 열림 | 현재 입력·현재 장 요약 우선 | 리사이즈로 재마운트하지 않음, 한글 조합·선택 범위 보존 |

메인 A는 넓은 화면에서 새 이야기 카드가 넓고 이어만들기 카드가 좁은 2열,
작은 화면에서는 새 이야기→이어만들기 순으로1열이다. 복구 정보는 이어만들기 안에 둔다.
카드/무대 높이를 목업 PNG 픽셀로 고정하지 않는다.

편집 F는 무대+현재 장 대본, G는 무대+글/좌/우/배경 조작이다. 큰 화면의
집중 패널은320~400px 시작안으로 검토하고, 글쓰기 가용 폭이 부족하면 아래로 이동한다.
무대 내 텍스트와 입력 폼을 서로 다른 편집본으로 만들지 않는다.

플레이는 무대와 대사 영역을 함께 레이아웃한다. 원작의 고정 대사 높이를 복사하지 않고
짧은 글/1000자 해설 모두를 읽을 수 있게 한다. 인물 크기를 비균일하게 줄이지 않는다.

### 장 개수·긴 제목

- 0개: 짧은 안내와 첫 장 추가. 장 선택/대본 이동은 빈 상태를 설명하며 자동 장 생성 없음.
- 1개: 실제 장 하나만. 이동 끝 비활성, 5개 빈 슬롯을 채우게 하지 않음.
- 5개: 순서·제목·여러 단계가 읽히고 선택 상세는 하나만 표시.
- 20개: 현재 장을 찾을 수 있는 목록 스크롤/선택기. 상세 입력 때문에 목록이 재초기화되지 않음.
- 긴 제목: 목록은 최대2줄 요약과 전체 제목 접근 수단, 상세 입력 원문은 생략하지 않음.

### 초점과 대화상자

- 화면/보기 전환은 같은 안정 ID를 유지하고 명시적으로 이동한 제목·입력에 초점.
- 장 선택 패널과 이미지 대화상자는 닫으면 연 조작으로 복귀.
- 이미지 미리보기 취소는 값 불변. 이 컷에 사용은 그 컷의 해당 필드만 변경.
- 장의 기본으로 되돌리기는 override 해제. 장 기본값 변경과 다른 조작.
- 각 대화상자 내부는 스크롤 가능하되 닫기·확인을 항상 찾을 수 있게 함.
- 목표: 본문/입력16px 이상, 보조14px 이상, 조작44px,200% 확대 대응.

## 4. 필드·상태 문구

필드의 유일한 대응표는 ADR의 필드 계약을 따른다. theme=큰 생각,
premise=한 줄 이야기, summary=이 장에서 일어나는 일이다. 나머지 필드는 접어서 보존한다.

| 상태 | 제안 문구/행동 |
|---|---|
| 기기 저장 확인 중 | 이 기기의 이야기를 확인하고 있어요. |

계정·클라우드 지원 상태는 표시하지 않는다. 현재 제공하지 않는 기능이므로
