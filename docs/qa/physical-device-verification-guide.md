# 모바일 물리 기기 검증 가이드 및 점검표

- 기준일: 2026-09-07
- 대상 브라우저: iOS Safari (iPhone / iPad), Android Chrome (Galaxy 등)
- 주 책임: QA·릴리스 책임자, 교육 UX 디자이너
- 목적: 데스크톱 Chrome DevTools의 가상 뷰포트 시뮬레이션으로 검증할 수 없는 모바일 OS 가상 키보드(소프트 키보드), 한글 IME 입력 조합, 노치/홈바 Safe Area 간섭, 실제 손가락 터치 조작성을 실기기에서 검증합니다.

---

## 1. 환경 준비 및 접속 방법

### 1-1. Mac 개발 서버 외부 바인딩 실행
터미널에서 아래 명령어로 로컬 네트워크 전체에 서버를 엽니다.

```bash
# 저장소 루트에서 실행
npm run dev -- -H 0.0.0.0 -p 3000
```

### 1-2. 모바일 기기 접속
- 테스트할 스마트폰/태블릿을 **Mac과 동일한 Wi-Fi 네트워크**에 연결합니다.
- 모바일 브라우저(Safari 또는 Chrome)를 열고 다음 주소로 접속합니다.
  - **접속 URL**: `http://192.168.219.104:3000` (또는 Vite 터미널에 표시되는 Network IP)

## 4. 실기기 사용자 정성 피드백 및 조치 현황 (2026-09-07)

### 4-1. 사용자 실기기 플레이 소감 및 발견된 핵심 UX 문제
- **첫 화면(StartScreen) 가시성 저하 및 인지 과부하**:
  - 모바일 세로 뷰포트에서 상단 배너, '새 이야기', '이어만들기', 'Excel 파일 열기', 'Google 시트', '예시 둘러보기' 등 수많은 선택지가 동시 노출되어 매우 난잡하고 무엇부터 해야 할지 모를 부담감을 줌.
- **스튜디오(제작 화면) 진입 후 조작 부담**:
  - 구성 5단계, 장 목록, 컷 목록, 무대/화자/배경 설정, 창작 메모 등 수많은 패널이 한꺼번에 쏟아져 초등학생 창작자에게 큰 인지 부하(Cognitive Overload)를 줌.

### 4-2. 조치 방향 및 진행 상태
- **방향**:
  1. 첫 화면: 크고 매력적인 `[ + 새 이야기 만들기 ]` 단일 Primary CTA 최우선 배치, 나머지(이어하기, 파일 불러오기, 예시)는 상단 탭이나 하단 보조 카드로 분리.
  2. 스튜디오 화면: 대본/글쓰기 집중 모드 기본 제공 및 꾸미기 요소 단계적 공개(Progressive Disclosure) 적용.
- **상태**: 코덱스(Codex)에 심층 UX 분석 및 화면 단순화 컴포넌트 재설계 프롬프트 전달 완료, 디자인 컨펌 대기.
