# 놀퀴즈 스토리 스튜디오

로그인 없이 기기 안에서 쓰고, Excel로 보관하며, 플레이로 고쳐 쓰는 학생용
비주얼 스토리게임 창작 도구입니다. `장(場)`은 이야기의 큰 흐름과 기본 무대를,
`컷(Cut)`은 한 화면의 대사·해설과 개별 연출을 뜻합니다.

## 현재 가능한 일

- **서재 책장과 책 꺼내기 Focus Stage**: 아름다운 동화책 서재에서 책을 고르면 원목 거치대에 올려 감성적으로 조명하며, 원작·놀스토리 읽기·공유 작품·편집하기를 직관적으로 선택
- **이야기 분기와 선택지**: 2/3개 선택지로 갈래를 나누고 컷을 분기하거나 다시 합류하는 비주얼 스토리 플레이
- **시네마틱 연출 및 표지**: 컷별 5종 시네마틱 효과(줌/패닝/페이드 등)와 책 앞·뒤표지, 커튼 전환 연출
- **기기 내 다중 보관함 & `.nolstory` 규격**: 최대 2개 창작 프로젝트를 기기에 격리 보관하고, 단일 `.nolstory` 파일로 백업 및 공유 읽기·고쳐쓰기 지원
- 예시 이야기, 이어쓰기 템플릿 또는 빈 작품에서 시작
- 3·4·5단계 이야기 뼈대를 만들고 한 장에 여러 이야기 단계 연결
- 장별 기본 배경·등장인물·화자를 정하고 컷별로 표정·배경 변경
- `대본 전체`와 `컷 꾸미기`를 오가며 같은 장·컷을 이어서 편집
- 캐릭터·배경 검색, 즐겨찾기와 최근 사용 기록
- 편집본을 기기에 자동 저장하고 플레이 버전에 명시적으로 적용
- 체크포인트 복구와 삭제 직후 되돌리기
- 처음부터 또는 원하는 장부터 플레이
- Excel 저장·불러오기와 공개 Google 시트 읽기

기본 제공 이미지의 저작권은 놀퀴즈에 있으며, 이 스토리게임의 작품 제작에
사용할 수 있습니다.

## 실행과 검사

Node.js `>=22.13.0`이 필요합니다.

```bash
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:3000`입니다.

```bash
npm run check
npm run build
npm test
```

공식 빈 Excel 양식은 다음 명령으로 다시 만듭니다.

```bash
npm run template:generate
```

## 저장과 자료 교환

편집본은 현재 브라우저의 격리된 로컬 저장소에 안전하게 자동 저장됩니다(기기당 최대 2개 작품 보관).
작품을 파일로 백업하거나 다른 기기로 옮길 때는 **`.nolstory` 파일로 내보내기/불러오기**를 사용하며,
기존 **Excel(.xlsx) 저장·불러오기**와 공개 **Google 시트 읽기**도 완벽히 지원합니다.
Excel과 `.nolstory` 파일은 서버에 업로드하지 않고 브라우저 로컬에서 안전하게 처리됩니다.

공개 보기 권한이 있거나 웹에 게시한 Google 시트는 주소로 한 번 읽어 옵니다.
웹에서 시트에 쓰거나 실시간 동기화하지 않습니다. 비공개 시트는 `.xlsx`로
내려받은 뒤 `Excel에서 불러오기`를 사용합니다.

## 공식 Excel 구조

현재 양식은 아래 8개 탭을 사용합니다.

- `시작하기`: 학생·교사용 작성 안내
- `이야기 구성`: 제목, 주제, 인물, 갈등과 3·4·5단계 뼈대
- `장의 흐름`: 장 제목, 여러 이야기 단계, 사건과 다음 장 연결
- `장의 자료`: 장의 기본 배경·인물·화자 후보
- `화자`: 작품에서 다시 쓸 표시 이름
- `컷 대본`: 대사·해설, 화자, 컷별 이미지와 연출 메모
- `창작 메모`: 이야기·장·컷에 연결하는 별도 창작 기록
- `리소스`: 웹에서 고를 수 있는 이미지 목록

화자 이름과 캐릭터 이미지는 서로 독립된 값입니다. 내부 호환 ID는 기존 파일을
계속 열기 위해 `chapter-*`, `scene-*` 형태를 유지하지만 학생 화면과 새 양식에는
`장`, `컷` 용어를 사용합니다. 이전 `작품`, `챕터`, `장면`, `대사` 탭도 계속
읽으며, 다시 저장하면 현재 8개 탭 구조로 바뀝니다.

## 현재 개발 상태와 다음 흐름

현재 저장소는 U1~U2 스튜디오 마일스톤, 이야기 분기(BR-01), 컷·표지 연출(CE-01, BC-01), 다중 보관함 및 .nolstory 규격(SP-A~F), 서재 책 꺼내기 Focus Stage(PR #20, #21)를 전체 완료하여 GitHub `main`에 반영한 상태입니다.
GitHub의 `main` 브랜치가 기준이며, 상태표에 현재 작업 하나만 `READY`로 둡니다.

```text
서재(책장 둘러보기)
  → 책 선택 (Focus Stage: 거치대 조명 & 액션 카드)
  → [놀스토리 읽기] / [편집하기 (스튜디오)] / [모두의 이야기]
  ↔ 대본·컷 꾸미기 ↔ 플레이
```

현재 대기열 및 마일스톤 현황은 다음과 같습니다.

| 작업 | 상태 | 내용 |
|---|---|---|
| U1-00 ~ U1-11 | `DONE` | 메인 진입, 이야기 구성, 장·컷 편집, 공통 무대, 플레이 위치·예시 격리·현재 컷 수정, 플레이 가독성 통합 검증 |
| U2-01 ~ U2-02 | `DONE` | 이어쓰기 템플릿(토끼와 자라, 옹고집전), 공통 프레임·모바일 정보량 정리, 160자 안내/나누기 |
| CE-01 / BC-01 | `DONE` | 컷 시네마틱 연출 5종, 책 앞·뒤표지 및 커튼 전환 연출 |
| BR-01 | `DONE` | 2/3지선다 선택지 분기 및 합류 비주얼 스토리 플레이 |
| SP-A ~ SP-F | `DONE` | 기기 내 2작품 격리 보관함, `.nolstory` 프로젝트/공유 파일 규격, 출처 보존 고쳐쓰기, 긴 글상자 가변 및 종이 대본 |
| Focus Stage (PR #21) | `DONE` | 서재 책 꺼내기 Focus Stage 감성 연출, 원목 거치대, 좌우 방향키 탐색, 2×2 선택 카드 |
| A1-02 | `BLOCKED` | 캐릭터 감정 세트 사람 승인·무대 검수 (외부 승인 대기) |

최신 기준선 검증 증거는 `npm run check` (0 오류), Vinext 빌드 포함 `npm test` **196/196 통과**, 브라우저 스모크 회귀(`qa:smoke`) 4개 스위트 통과, GitHub Actions CI 통과입니다.

제품 범위(Scope)에는 로그인, 학생 작품 중앙 서버, 실시간 다중 기기 공동 편집, Google OAuth, 학생용 AI 자동 작성·이미지 생성, 공개 작품 커뮤니티가 포함되지 않습니다. 2/3개 선택지 분기 및 합류(BR-01)는 정식 지원하며, 작품은 로컬 기기 및 `.nolstory`/`Excel` 파일로 학생이 직접 소유·보관합니다.
