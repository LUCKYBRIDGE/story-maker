# 놀퀴즈 스토리 스튜디오

로그인 없이 기기 안에서 쓰고, Excel로 보관하며, 플레이로 고쳐 쓰는 학생용
비주얼 스토리게임 창작 도구입니다. `장(場)`은 이야기의 큰 흐름과 기본 무대를,
`컷(Cut)`은 한 화면의 대사·해설과 개별 연출을 뜻합니다.

## 현재 가능한 일

- 예시 이야기, 이어쓰기 템플릿 또는 빈 작품에서 시작
- 3·4·5단계 이야기 뼈대를 만들고 한 장에 여러 이야기 단계 연결
- 장별 기본 배경·등장인물·화자를 정하고 컷별로 표정·배경 변경
- `대본 전체`와 `컷 꾸미기`를 오가며 같은 장·컷을 이어서 편집
- 캐릭터·배경 검색, 즐겨찾기와 최근 사용 기록
- 편집본을 기기에 자동 저장하고 플레이 버전에 명시적으로 적용
- 체크포인트 복구와 삭제 직후 되돌리기
- 처음부터 또는 원하는 장부터 플레이
- Excel 저장·불러오기와 공개 Google 시트 읽기

기본 제공 이미지의 저작권은 놀퀴즈에 있으며, 이 스토리게임의 작품 제작에
사용할 수 있습니다.

## 실행과 검사

Node.js `>=22.13.0`이 필요합니다.

```bash
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:3000`입니다.

```bash
npm run check
npm run build
npm test
```

공식 빈 Excel 양식은 다음 명령으로 다시 만듭니다.

```bash
npm run template:generate
```

## 저장과 자료 교환

편집본은 현재 브라우저에 자동 저장됩니다. 브라우저 데이터 삭제, 시크릿 모드,
기기 교체까지 복구하는 서버 백업은 아니므로 중요한 작품은 `Excel로 저장`해
별도 보관해야 합니다. Excel은 서버에 업로드하지 않고 브라우저에서 읽습니다.

공개 보기 권한이 있거나 웹에 게시한 Google 시트는 주소로 한 번 읽어 옵니다.
웹에서 시트에 쓰거나 실시간 동기화하지 않습니다. 비공개 시트는 `.xlsx`로
내려받은 뒤 `Excel에서 불러오기`를 사용합니다.

## 공식 Excel 구조

현재 양식은 아래 8개 탭을 사용합니다.

- `시작하기`: 학생·교사용 작성 안내
- `이야기 구성`: 제목, 주제, 인물, 갈등과 3·4·5단계 뼈대
- `장의 흐름`: 장 제목, 여러 이야기 단계, 사건과 다음 장 연결
- `장의 자료`: 장의 기본 배경·인물·화자 후보
- `화자`: 작품에서 다시 쓸 표시 이름
- `컷 대본`: 대사·해설, 화자, 컷별 이미지와 연출 메모
- `창작 메모`: 이야기·장·컷에 연결하는 별도 창작 기록
- `리소스`: 웹에서 고를 수 있는 이미지 목록

화자 이름과 캐릭터 이미지는 서로 독립된 값입니다. 내부 호환 ID는 기존 파일을
계속 열기 위해 `chapter-*`, `scene-*` 형태를 유지하지만 학생 화면과 새 양식에는
`장`, `컷` 용어를 사용합니다. 이전 `작품`, `챕터`, `장면`, `대사` 탭도 계속
읽으며, 다시 저장하면 현재 8개 탭 구조로 바뀝니다.

## 현재 개발 상태와 다음 흐름

현재 저장소는 U1 화면 정합화 작업을 U1-09까지 완료한 상태입니다. GitHub의
`main` 브랜치가 기준이며, 상태표에 현재 작업 하나만 `READY`로 둡니다.

```text
메인
  → 이야기 구성
  ↔ 대본·컷 쓰기
  ↔ 플레이
  → 플레이에서 본 컷 고치기
```

현재 대기열은 다음과 같습니다.

| 작업 | 상태 | 내용 |
|---|---|---|
| U1-01 ~ U1-09 | `DONE` | 메인 진입, 이야기 구성, 장·컷 편집, 공통 무대, 플레이 위치·예시 격리·현재 컷 수정 |
| U1-10 | `READY` | 원작을 참고한 플레이 가독성·반응형 |
| U1-11 | `BLOCKED` | 통합 호환·반응형 인수와 문서 마감. U1-10 뒤 시작 |
| A1-02 | `DEFERRED` | 캐릭터 감정 세트 승인·무대 검수. 원본과 작업 카드는 보존 |

U1-10을 시작할 때는 다음 순서를 지킵니다.

1. `AGENTS.md`와 [개발 상태표](docs/storygame-development-status.md)를 읽고 유일한 `READY` 작업을 확인합니다.
2. [AI 실행 런북](docs/storygame-ai-implementation-runbook.md)과 해당 원자 작업 카드를 읽습니다.
3. 작업 카드의 허용 파일 안에서만 구현하고, 기존 작품·Excel·자산 ID·미커밋 사용자 작업을 보존합니다.
4. 좁은 검사 → `npm run check` → `npm test` → 대표 화면 실제 흐름 순으로 검증합니다.
5. 완료 증거를 상태표에 기록하고 다음 작업 하나만 `READY`로 엽니다. 같은 세션에서 다음 작업은 구현하지 않습니다.

U1-09의 최신 증거는 좁은 검사 25/25, `npm run check`, Vinext 빌드 포함
`npm test` 107/107, `git diff --check`, Chrome 1440×900·390×844 실제 흐름입니다.
예시 재생·학생 작품·편집 위치·현재 컷 수정·삭제된 컷 안전 복귀를 확인했습니다.
네이티브 iOS/Android 키보드는 도구가 없어 아직 검증하지 않았으며 U1-11에서 다룹니다.

제품 범위에는 로그인, 학생 작품 서버, 실시간 공동 편집, Google OAuth, 학생용 AI
자동 작성·이미지 생성, 공개 작품 커뮤니티, 선택지·분기형 플레이가 포함되지 않습니다.
작품은 기기에 저장하고, 중요한 결과물은 Excel로 별도 보관합니다.
