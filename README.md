# 놀퀴즈 스토리 스튜디오

로그인 없이 기기 안에서 쓰고, Excel과 `.nolstory` 파일로 보관·이동하며, 직접 읽고 플레이하면서 고쳐 쓰는 학생용 비주얼 스토리게임 창작 도구이다. `장(場)`은 이야기의 큰 흐름과 기본 무대를, `컷(Cut)`은 한 화면의 대사·해설과 개별 연출을 뜻한다.

## 현재 가능한 일

- **메인 화면**: `이야기 변경` / `나만의 이야기` / `서재 입장`의 상단 메뉴와, 현재 선택한 기본 작품을 바로 여는 `이야기 읽기`를 제공한다.
- **서재와 책 선택**: 반응형 목재 책장에서 기본 이야기·내 작품·공유 작품을 둘러보고, 책을 고르면 확대된 선택 화면에서 읽기·편집·공유 작품 흐름으로 진입한다.
- **새 작품 시작**: 서재의 빈 윤곽 책 또는 창작 허브에서 빈 작품, 전래동화 이어쓰기, 외부 파일 가져오기를 시작한다.
- **이야기 분기와 선택지**: 2/3개 선택지로 갈래를 나누고 컷을 분기하거나 다시 합류하는 비주얼 스토리 플레이를 지원한다.
- **시네마틱 연출 및 표지**: 컷별 시네마틱 효과와 책 앞·뒤표지, 커튼 전환을 지원한다.
- **기기 내 다중 보관함 & `.nolstory` 규격**: 최대 2개 창작 프로젝트를 기기에 격리 보관하고, `.nolstory` 파일로 백업·이동·공유 읽기·허용된 고쳐쓰기를 지원한다.
- **읽기 화면 연속성**: 같은 탭에서 화면 위치, 읽던 컷, 실제 선택 경로, 표지/종료 상태 등을 복원한다. 저장 불가 환경에서는 영구 복원을 보장하지 않는다.
- **읽기 표시 설정**: 기본 35%인 하단 글상자를 20~60% 범위에서 조절하고, 인물 그룹별 표시 크기를 조정·초기화할 수 있다.
- 예시 이야기, 이어쓰기 템플릿 또는 빈 작품에서 시작한다.
- 3·4·5단계 이야기 뼈대를 만들고 한 장에 여러 이야기 단계를 연결한다.
- 장별 기본 배경·등장인물·화자를 정하고 컷별로 표정·배경을 변경한다.
- `대본 전체`와 `컷 꾸미기`를 오가며 같은 장·컷을 이어서 편집한다.
- 캐릭터·배경 검색, 즐겨찾기와 최근 사용 기록을 지원한다.
- 편집본을 기기에 자동 저장하고 플레이 버전에 명시적으로 적용한다.
- 체크포인트 복구와 삭제 직후 되돌리기를 지원한다.
- 처음부터 또는 원하는 장부터 플레이한다.
- Excel 저장·불러오기와 공개 Google 시트 읽기를 지원한다.

기본 제공 이미지의 저작권은 놀퀴즈에 있으며, 이 스토리게임의 작품 제작에 사용할 수 있다.

## 실행과 검사

Node.js `>=22.13.0`이 필요하다.

```bash
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:3000`이다.

```bash
npm run check
npm run build
npm test
npm run qa:smoke
```

공식 빈 Excel 양식은 다음 명령으로 다시 만든다.

```bash
npm run template:generate
```

## 저장과 자료 교환

편집본은 현재 브라우저의 격리된 로컬 저장소에 자동 저장된다. 현재 정책은 기기당 최대 2개 창작 프로젝트 보관이다.

작품을 파일로 백업하거나 다른 기기로 옮길 때는 **`.nolstory` 파일 내보내기/불러오기**를 사용한다. 기존 **Excel(.xlsx) 저장·불러오기**와 공개 **Google 시트 읽기**도 유지한다. Excel과 `.nolstory` 파일은 중앙 작품 서버에 자동 업로드하지 않고 브라우저에서 처리한다.

공개 보기 권한이 있거나 웹에 게시한 Google 시트는 주소로 한 번 읽어 온다. 웹에서 시트에 쓰거나 실시간 동기화하지 않는다. 비공개 시트는 `.xlsx`로 내려받은 뒤 `Excel에서 불러오기`를 사용한다.

공유 작품의 고쳐쓰기는 파일에 포함된 복제 허용 정책과 현재 프로젝트 슬롯 제한을 따른다. 원본과 편집본은 별도 프로젝트로 취급하며 출처 정보를 보존한다.

## 공식 Excel 구조

현재 양식은 아래 8개 탭을 사용한다.

- `시작하기`: 학생·교사용 작성 안내
- `이야기 구성`: 제목, 주제, 인물, 갈등과 3·4·5단계 뼈대
- `장의 흐름`: 장 제목, 여러 이야기 단계, 사건과 다음 장 연결
- `장의 자료`: 장의 기본 배경·인물·화자 후보
- `화자`: 작품에서 다시 쓸 표시 이름
- `컷 대본`: 대사·해설, 화자, 컷별 이미지와 연출 메모
- `창작 메모`: 이야기·장·컷에 연결하는 별도 창작 기록
- `리소스`: 웹에서 고를 수 있는 이미지 목록

화자 이름과 캐릭터 이미지는 서로 독립된 값이다. 내부 호환 ID는 기존 파일을 계속 열기 위해 `chapter-*`, `scene-*` 형태를 유지하지만 학생 화면과 새 양식에는 `장`, `컷` 용어를 사용한다. 이전 `작품`, `챕터`, `장면`, `대사` 탭도 계속 읽으며, 다시 저장하면 현재 8개 탭 구조로 바뀐다.

## 현재 기준선

2026-09-12 기준 제품 기능 기준선은 `codex/library-craft`의 `a0809e0 feat: refine library and reading experience`가 **PR #23**으로 `main`에 병합된 상태이다. 병합 직후 제품 기준 merge commit은 `a18b7ca`이다.

PR #23에는 다음 묶음이 포함되어 있다.

- HOME-01: 상단 `이야기 변경` / `나만의 이야기` / `서재 입장`, 하단 `이야기 읽기`
- LIB-02~LIB-11: 반응형 서재 재질·배치·전경·책 안착·빈 윤곽 책 생성 흐름
- PLAY-UI-01: 읽기 글상자 20~60%, 인물 그룹별 표시 크기, 같은 탭 화면·읽기 경로 복원
- 기존 U1~U2, BR-01, CE-01/BC-01, SP-A~SP-F 기능 유지

현재 대표 흐름은 다음과 같다.

```text
메인
  ├─ 이야기 읽기 → 현재 선택 기본 작품의 책 표지 → 이야기 펼치기
  ├─ 이야기 변경 → 서재
  ├─ 서재 입장 → 서재 → 책 선택 → 읽기 / 편집 / 공유 작품
  └─ 나만의 이야기 → 창작 허브 → 새 작품 / 이어만들기 / 파일 가져오기

편집
  ↔ 대본 전체 / 컷 꾸미기
  → 플레이에 적용
  → 책 표지 / 플레이 / 선택 경로 / 뒤표지
```

`npm test` 기준 단위·회귀 검사는 PR #23 작업 시 **198개**까지 통과했다. PR #23 병합 후 GitHub Pages 배포는 성공했다. 병합 직후 CI의 브라우저 스모크는 제거된 `.entry-template-options` DOM을 기다리던 과거 QA 시나리오 때문에 실패했으나, **PR #24 기준선 동기화 작업에서 `story-flow`, `sticky-memos`, `pinky-examples`, 교실용 공용 fixture를 현행 진입·복원 흐름에 맞게 수정했다. CI run #100에서 정적 검사, 빌드·테스트, Pages artifact, 브라우저 스모크, 모바일 터치·시트 fixture가 모두 성공했다.**

현재 열린 별도 유지보수 PR로 **#14 의존성 보안 정리**가 있으며, 제품 UI 기준선과는 분리해 관리한다. 해당 PR은 현재 `main`보다 오래된 기준에서 시작했으므로 병합 전 최신 `main`과 재정렬이 필요하다.

제품 범위(Scope)에는 로그인, 학생 작품 중앙 서버, 실시간 다중 기기 공동 편집, Google OAuth, 학생용 AI 자동 작성·이미지 생성, 공개 작품 커뮤니티가 포함되지 않는다. 작품은 로컬 기기 및 `.nolstory`/Excel 파일로 학생이 직접 소유·보관하는 구조가 기준이다.
